# Как подбирается контекст вокруг факта

Вход — факт из родословной: координаты и дата. Выход — записи из всех слоёв,
отсортированные по тому, насколько они объясняют обстановку вокруг этого факта.

```python
from histctx import ContextEngine, Fact

engine = ContextEngine(records)
matches = engine.find(
    Fact(lat=59.86, lon=38.37, year=1899, label="венчание, Кириллов"),
    radius_km=60,
    year_window=25,
    per_layer_cap=3,
)
for m in matches:
    print(m.score, m.record.title, m.explain())
```

Выдача складывается из двух видов записей: точек на местности и событий,
у которых точки нет вовсе — ревизии, реформы, голодные годы. Вторые
подбираются по губернии и годам, см. «События без точки» ниже.

## Формула

Оценка складывается из трёх частей и всегда лежит в диапазоне 0…1:

```
score = (0.45 × близость + 0.45 × совпадение по времени + 0.10) × специфичность
```

- **близость** — 1.0 в точке факта, 0.0 на границе радиуса;
- **совпадение по времени** — 1.0 при пересечении интервалов, дальше линейный
  спад до края окна; у записи без датировки — 0.12;
- **специфичность** — понижает записи с широкой датировкой: «19 в.» подходит
  почти ко всему и не должен вытеснять точную дату;
- слагаемое 0.10 — базовый вес самого факта попадания в радиус.

Формула намеренно простая. Пользователь должен понимать, почему запись
показана, поэтому каждое совпадение несёт человекочитаемое объяснение:

```
[0.95] Материалы бюро Тенишева  Горицы  1897–1901  в 6 км; совпадает по времени
[0.82] Прокудин-Горский         Кириллов 1903–1916 в том же населённом пункте; разница 4 лет
```

## Параметры

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `radius_km` | 50 | Радиус поиска |
| `year_window` | 25 | На сколько лет за пределами факта запись ещё считается уместной |
| `include_territorial` | да | Показывать ли события без точки |
| `layers` | все | Ограничить набор слоёв |
| `per_layer_cap` | нет | Не более N записей на слой — плотный слой не вытеснит остальные |
| `min_score` | 0 | Порог отсечения |
| `limit` | 50 | Размер выдачи |

`per_layer_cap` стоит задавать почти всегда. Без него 60 000 населённых мест
заполнят всю выдачу и вытеснят единственную ценную запись из слоя эпидемий.

## События без точки

Ревизия, отмена крепостного права, голод 1891 года, депортация — всё это
объясняет документ о предке лучше соседнего храма, но координат не имеет.
Такие записи (`scope = region` или `state`) хранятся отдельно от точек и
попадают в выдачу по другому правилу: вместо расстояния — совпадение
территории.

```
score = (0.45 × территория + 0.45 × совпадение по времени + 0.10) × специфичность
```

- **территория** = 1.0, если губерния факта названа в событии поимённо;
- **территория** = 0.65 у события на всё государство: под него подходит любой
  факт этих лет, значит, объясняет оно меньше;
- остальные слагаемые те же, что и для точек, — формула одна.

Губерния факта берётся из `Fact(region=...)`, а если не задана — определяется
по ближайшим записям, у которых губерния проставлена:

```python
engine.resolve_region(fact)      # ('Новгородская губерния', 'по ближайшим записям')
```

Если губерния так и не определилась, губернские события **не показываются**.
Приписать факту чужую губернию хуже, чем промолчать: событие выглядит
достоверно и уводит поиск не туда. События на всё государство при этом
показываются всегда — им губерния не нужна.

В командной строке:

```bash
python3 scripts/context.py --lat 53.20 --lon 50.15 --year 1891 \
    --region "Самарская губерния"

  [1.00] Указы, реформы и потрясения   1891–1892  Голод 1891–1892 годов
         Самарская губерния — в числе затронутых; совпадает по времени
  [0.76] Указы, реформы и потрясения   1887–1899  Отмена подушной подати
         действовало на всей территории: Российская империя; совпадает по времени
```

Названия территорий сравниваются с точностью до типа единицы и падежа
(`histctx.geo.same_region`): за полтора века одна и та же местность звалась
губернией, округом и областью, и в источниках это записано по-разному.

## Что исключается автоматически

Записи с `confidence = "not_an_event"` — воинские части, корабли, персоналии —
в индекс не попадают. Поведение меняется параметром конструктора:

```python
ContextEngine(records, exclude_confidence=[])   # включить всё
```

## Подбор без даты

Если у факта нет года (`Fact(..., year=None)`), временная составляющая не
учитывается и подбор идёт только по расстоянию. Это рабочий режим: место
рождения часто известно, а год — нет.

## Производительность

Индекс — решётка 1°×1° (`histctx.geo.SpatialIndex`). На 4 149 точках поиск
занимает доли миллисекунды; на сотнях тысяч записей решётка остаётся
приемлемой. Если объём вырастет за миллион, разумный следующий шаг — перенести
поиск в PostGIS с индексом по `geography` и по `(year_from, year_to)`, сохранив
ту же формулу ранжирования.
