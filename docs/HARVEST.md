# Сбор данных: что откуда и как запускать

Репозиторий приводит разные источники к одной записи «что, где, когда,
откуда». Здесь — как этот сбор запускается на практике: какие домены нужны,
какой скрипт что делает и в каком порядке.

## Домены, которые нужно открыть

Сбор идёт из сети, и в закрытом окружении (Claude Code on the web, CI без
внешнего доступа) он не пойдёт: попытка соединения обрывается на CONNECT.

Без части доменов работает часть сбора: Викиданные, PastVu и погода
независимы друг от друга.

Список будет расти. Каталог источников открыт (см. `docs/CATALOG.md`, раздел
«Каталог открыт»), кандидаты приходят из постоянного поиска
(`docs/DISCOVERY.md`), и подключение нового источника обычно означает новый
домен в этой таблице. Строка сюда добавляется вместе с самим сборщиком — чтобы не
выяснять задним числом, зачем окружению понадобился очередной адрес.

Две строки таблицы — `www.demoscope.ru` и `overpass-api.openhistoricalmap.org`
— исключение из правила «строка вместе со сборщиком»: слои `census_1897_uezd`
и `openhistoricalmap` объявлены проходом по каталогу 23.08.2026, сборщиков у
них ещё нет, а адреса понадобились уже на проверке — без них следующий
проход снова упрётся в CONNECT и будет гадать, зачем эти домены нужны.
Третья такая строка, `dataverse.harvard.edu`, исключением быть перестала:
22.10.2026 у набора по голоду появился сборщик. Наборы Imperiia Project
(1820-е годы, CC BY-NC-SA 4.0) стоят в журнале дискавери со статусом «на
очереди»; лежат они на том же `dataverse.harvard.edu`.

## Порядок

```bash
# 0. Ядро: нормализовать исходные файлы проекта и подборку событий
python3 scripts/build_core.py

# 1. Викиданные: сверка Q-номеров, живая проба, потом сбор
python3 scripts/harvest.py --check
python3 scripts/harvest.py --probe --layer churches
python3 scripts/harvest.py --all

# 1a. Переименования населённых мест: свой сборщик, но те же Викиданные
python3 scripts/harvest_renamed.py --probe
python3 scripts/harvest_renamed.py --build

# 2. Фотографии PastVu: сначала проба формата ответа
python3 scripts/harvest_pastvu.py --probe
python3 scripts/harvest_pastvu.py --estimate --all          # сколько там записей
python3 scripts/harvest_pastvu.py --all --step 1.0          # обход: часы, не минуты
python3 scripts/harvest_pastvu.py --all --step 1.0 --resume # продолжить прерванный

# 3. Населённые места: сети не требуют, набор идёт вместе с пакетом
pip install geonamescache
python3 scripts/harvest_geonames.py --probe
python3 scripts/harvest_geonames.py --build

# 4. Лагерные управления: сначала проверка ответа API
python3 scripts/harvest_gulag.py --check
python3 scripts/harvest_gulag.py --build
python3 scripts/export_gulag_xlsx.py                        # книга для чтения глазами

# 5. Границы и итоги переписей: heiDATA (CC BY 4.0) и RISTAT (CC0)
python3 scripts/harvest_admin_gis.py --check
python3 scripts/harvest_admin_gis.py --build

# 6. Границы государств 1886–1960: CShapes 2.0 (CC BY-NC-SA 4.0)
python3 scripts/harvest_cshapes.py --check
python3 scripts/harvest_cshapes.py --build

# 7. Урожай и цены по губерниям (RISTAT/ERRHS): сначала проба одной таблицы
python3 scripts/harvest_errhs.py --check
python3 scripts/harvest_errhs.py --build

# 8. Засухи по годичным кольцам: сначала проба формата набора
python3 scripts/harvest_drought.py --probe
python3 scripts/harvest_drought.py --build

# 9. Погода: ряды GHCN, проба, сборка слоёв. Идёт после границ —
#    губернию станции берём из полигонов 1897 года (иначе --no-regions)
python3 scripts/harvest_weather.py --fetch
python3 scripts/harvest_weather.py --probe data/raw/meteo/ghcn.csv
python3 scripts/harvest_weather.py --build data/raw/meteo/ghcn.csv \
    --source "GHCN-M v4, NOAA NCEI" \

    --license "данные NOAA/NCEI — общественное достояние (работа правительства США), ограничений на использование нет; NOAA требует ссылки на набор и гарантий точности не даёт"

# 10. Стачки и рабочие волнения 1895–1904 годов: свод IISH (CC0)
python3 scripts/harvest_strikes.py --probe
python3 scripts/harvest_strikes.py --build

# 11. Голод 1891–1892 годов по уездам: набор В. Чарныш, Harvard Dataverse (CC0 1.0).
#     Идёт после границ (шаг 5): уезды сверяются с districts_1897.geojson
python3 scripts/harvest_famine_1891.py --check
python3 scripts/harvest_famine_1891.py --build

# 12. Засухи по кольцам за пределами ERDA: Great Eurasian Drought Atlas, Zenodo
#     (CC BY 4.0). Нужен h5py (pip install h5py) — только этому сборщику; идёт
#     после границ (шаг 6): Китай и Монголию отсекают полигоны CShapes
python3 scripts/harvest_drought_geda.py --check --compare-erda
python3 scripts/harvest_drought_geda.py --build

#     Подолии: сервер карт HURI MAPA (права не выяснены, берутся факты).
#     Идёт после границ (шаг 5): губерния 1897 года — по их полигонам
python3 scripts/harvest_huri.py --check
python3 scripts/harvest_huri.py --build
# 14. Голод 1932–1933 годов по районам и губернская смертность 1871–1914 годов:
#     пакет Маркевича, Науменко, Цянь (Zenodo) и районы УССР Rozenas, Zhukov
#     (Harvard Dataverse, CC0). Идёт после границ (шаг 5): губерния по центроиду
python3 scripts/harvest_famine_1933.py --check

python3 scripts/harvest_mobilization_1914.py --build

python3 scripts/harvest_city_population.py --build
# 18. Оккупация и освобождение городов 1941–1945: справочник 1985 года, soldat.ru.

python3 scripts/harvest_occupation.py --check
python3 scripts/harvest_occupation.py --build

#     и карточки базы НАРБ (db.narb.by, права не выяснены). Полный обход карточек —
#     часы; --build пишет то, что уже в кэше
python3 scripts/harvest_burned_villages.py --probe
python3 scripts/harvest_burned_villages.py --narb-all      # можно прерывать и продолжать
python3 scripts/harvest_burned_villages.py --build
# 20. Церковные приходы: Викиданные, тот же harvest.py, но с @place, @label
#     и @frame. Идёт после границ (шаг 5 и 6): рамка — губернии 1897 года
#     и CShapes из data/out/boundaries
python3 scripts/harvest.py --probe --layer parishes
python3 scripts/harvest.py --layer parishes

# Выгрузка любого собранного слоя в XLSX — записи, сводка, лист об источнике
python3 scripts/export_layer_xlsx.py --layer repressions
```

Восьмая команда сети не требует вовсе: `python3 scripts/export_xlsx.py
--layer <слой>` переводит **уже собранный** слой в таблицу с русскими
заголовками, читая его с диска. Нужна она потому, что xlsx пишется только
вместе со сбором, а в репозиторий выгрузка не идёт (`data/out/*.xlsx`
в `.gitignore`): после `git clone` посмотреть слой таблицей иначе нечем.
`--list` печатает, что уже собрано.

Населённые места — единственный слой, который собирается в закрытом
окружении: реестры пакетов (`pypi.org`, `files.pythonhosted.org`) открыты там,
где закрыты сайты источников, а набор GeoNames приезжает внутри пакета
`geonamescache`. Данные под CC BY 4.0 — ссылка на GeoNames проставляется в
каждой записи.

Свод стачек скачивается один раз в `data/cache/strikes/` (книга xlsx,
2 МБ) и пересобирается тем же `--build`. Записи территориальные, GeoJSON у
них не бывает, поэтому слой пишется в `data/out/labour_conflicts.json` — он
идёт в репозиторий, как цены и погода по губерниям, — и в
`data/out/jsonl/`. Так же устроены итоги переписей:
`harvest_admin_gis.py --build` пишет `data/out/admin_1897_gis.json`.

Ингестированного TSV, по которому писался разбор, после переезда коллекции
IISH на `dataverse.nl` нет: свод лежит книгой `Micro_Russia_1895-1904.xlsx`.
Заголовки книги — с пробелами и подчёркиваниями («Begin Year», «Cause_1»),
а TSV выбрасывал их при ингесте; разбор сводит заголовки к прежним именам
(`strikes.column_key`). Сверено при переходе 24.10.2026: строк те же 7886,
с вызовом полиции или войск те же 260. Старый TSV по-прежнему читается
через `--from-file`.

Набор по голоду 1891–1892 годов скачивается в `data/raw/famine_1891/` (шесть
мегабайт, в репозиторий не идёт) и пересобирается тем же `--build`; записи
четырёх видов — уезды, губернии, холера 1892 года, сверхсмертность по
годам — идут в `data/out/famine_1891.json` (в репозиторий) и в
`data/out/jsonl/`, полигоны уездов — в `data/out/boundaries/`, и они в
репозиторий тоже идут. Подробности — раздел «Голод 1891–1892 годов
по уездам».

Слои сервера HURI MAPA скачиваются в `data/raw/huri/` (около 60 МБ, в
репозиторий не идёт) и пересобираются тем же `--build`; подложка — в
`data/out/boundaries/`, перепись 1926 года — в
`data/out/census_1926_raion.json` и `jsonl/`, поселения Подолии — в
`geojson/` и `jsonl/`. Подробности — раздел «Районы УССР и перепись 1926
года: HURI MAPA».
Пакет по голоду 1932–1933 годов (`v3.zip`, 12,8 МБ) и `main_data.Rdata`
(5 МБ) скачиваются в `data/raw/famine_1933/` и в репозиторий не идут. В
репозиторий идут точки — `data/out/geojson/famine_1933.geojson` (5,9 МБ),
записи без точки — `data/out/famine_1933.json` и
`data/out/mortality_1871_1914.json`, полигоны районов УССР —
`data/out/boundaries/famine_1933_ukr_rayons.geojson`. Подробности — раздел
«Голод 1932–1933 годов по районам».
Три пакета воспроизведения, подключённые 24.10.2026, скачиваются в
`data/raw/reforms_1851/` (2 МБ), `data/raw/mobilization_1914/` (3 МБ) и
`data/raw/city_population/` (архив на 27 МБ и выгрузки русских названий
GeoNames по трём странам, 15 МБ); всё это в `.gitignore`. В репозиторий идут
записи: `data/out/peasant_unrest_1851.json`, `reforms_uezd.json`,
`mobilization_1914.json` (без точки) и `geojson/city_population.geojson`.
Подробности — раздел «Волнения, реформы, мобилизация и города: три пакета
Dataverse».
Страницы справочника «Освобождение городов» и набор Grunewald для сверки
скачиваются в `data/raw/occupation_cities/` (около 850 КБ, в репозиторий не
идут), ответы Викиданных — в `data/cache/occupation_cities/`. `--check`
скачивает страницы заново, `--build` берёт их из кэша. Записи с точкой идут в
`data/out/geojson/occupation_cities.geojson` (1,6 МБ), без точки — в
`data/out/occupation_cities.json`; оба файла в репозиторий идут. Подробности —
раздел «Оккупация и освобождение городов».

Границы и переписи скачиваются один раз и остаются в `data/cache/boundaries/`:
наборы весят мегабайты и с 2015 года не менялись. Кэш в репозиторий не идёт
(`data/cache/` в `.gitignore`), пересобрать его — тот же `--build`.

Общее правило у всех сборщиков: **первый запуск — проверочный**. `--check` сверяет
Q-номера классов с Викиданными, `--probe` печатает реальный ответ сервиса или
реальные колонки файла. Собрать не то молча хуже, чем остановиться: ошибку
формата в выгрузке на сотни тысяч записей потом не найти.

## Викиданные: сбор в две ступени

Первая редакция запросов отбирала объекты географической рамкой
(`SERVICE wikibase:box`) поверх транзитивного замыкания по классу
(`wdt:P31/wdt:P279*`). Против живого сервиса такой запрос не выполняется:
рамка РИ/СССР слишком велика, и сбор упирается в лимит времени — HTTP 504.
Проверено на всех одиннадцати запросах: не прошёл ни один. Ни `--paged`, ни
`--page-size` не помогают — `ORDER BY ?item` поверх такого результата сам по
себе неподъёмен.

Рабочий способ — отбор по государству (`wdt:P17`) вместо рамки и разделение
работы на две ступени:

1. **Список Q-номеров с координатами** — по одному запросу на государство.
   Без меток, без `OPTIONAL`, без сортировки: только то, что дёшево.
2. **Подробности к ним** — чанками по тысяче через `VALUES ?item`. Дорогие
   соединения выполняются на заранее известном списке, а не на результате
   поиска, и укладываются в лимит.

Территорию РИ/СССР не покрывает ни одно нынешнее государство, поэтому обход
идёт по семнадцати государствам-преемникам (`COUNTRIES` в
`src/histctx/sources/wikidata.py`). Рамка остаётся вторым ситом: координата
всё равно проверяется через `histctx.geo.in_bbox`.

Слой переводится на новый способ директивой `@scope country` в заголовке
`.rq`. Собираются те классы, что объявлены директивами `@qid`, — отдельного
списка классов не нужно. Сузить отбор можно директивой `@filter`, её строки
попадают в условие первой ступени. Файлы без `@scope` работают по-старому.

Дату объекта вторая ступень спрашивает у двух свойств: сначала P571 («дата
основания»), а если её нет — P1619 («дата официального открытия»). Для станций
это решает всё: на выборке в 2003 объекта по России P571 нашлась у 124 (6%),
P1619 — у 1291 (64%). Слоям, где P1619 не заполняют, добавка ничего не меняет;
событий (`@kind event`) она не касается — у них свои свойства.
### Неполный сбор не затирает полную выгрузку

Осечка на одной стране сбор не отменяет: потерять область хуже, чем потерять
весь слой, — но записать усечённое поверх полного значит потерять всё, только
молча. Живой случай 29.08.2026: у слоя иных конфессий Россия и Польша ответили
`HTTP 504`, остальные пятнадцать государств прошли нормально, и слой из
**2 964 записей записался бы как 1 974**. Пустой результат сбор защищал и
раньше («ПУСТО — файлы не перезаписаны»), а усечённый выглядел для него
обычным.

Теперь `collect_layer` складывает каждую потерю в список `failures` — и
осечку страны на первой ступени, и потерянный чанк на второй, — а
`scripts/harvest.py` перед записью спрашивает `refuse_to_write`. Проверок две:

1. **Был ли отказ.** Любая запись в `failures` — выгрузка не пишется.
2. **Не усох ли слой.** Даже когда отказов нет: сервис умеет ответить
   успехом и пустотой сразу. Порог — `SHRINK_LIMIT = 0.9` от прежней
   выгрузки. Викиданные живут, и потеря одной записи из 1045 (так вышло у
   рудников) — норма; треть слоя — нет.

В обоих случаях прежние файлы остаются на месте, а сбор говорит, что
случилось, и предлагает пересобрать слой позже. Если потеря осознанная —
`--force` пишет как есть и печатает, что именно перезаписано.

### Название приходит на языке места

Вторая ступень спрашивает подпись у `SERVICE wikibase:label`, и до 29.08.2026
она просила её только по-русски и по-английски. У волынской церкви, латвийского
имения или финского рудника русской подписи может не быть вовсе, и сервис
в таком случае возвращает не пустоту, а голый Q-номер: на карту шло
«Q16617021». Так осталось без названия **18 479 записей — каждая восьмая
в выгрузке**: 6 176 храмов, 4 145 кладбищ, 2 951 станция, 2 279 усадеб.

Список языков (`LABEL_LANGS` в `sources/wikidata.py`) теперь перечисляет языки
территории. Замер на 223 безымянных записях из четырнадцати слоёв: подпись
хотя бы на одном языке есть **у всех до единой**, чаще всего польская (65%),
затем литовская, украинская, финская, латышская, белорусская, румынская,
эстонская. Языки территории закрывают 99%; двух объектов, подписанных только
по-французски, хватило, чтобы дописать в хвост `fr` и `nl`.

Порядок в списке важен не меньше состава: `ru` и `en` стоят первыми, а сервис
берёт первый доступный язык. Проба на 500 храмах — 250 безымянных и 250 с
названием — дала 249 новых имён и **ни одного изменённого старого**; ответ
подорожал с 5,0 до 6,8 секунды на чанк в тысячу Q-номеров.

Что при этом нужно помнить: название приходит на языке места — «Cerkiew
Narodzenia św. Jana Chrzciciela w Orłowie», «Augškalnes Svētās Ģimenes Romas
katoļu baznīca». Для карты это правильное, местное написание, но искать по
нему по-русски нельзя: поиск по написаниям — задача указателя
`name_variants.json`, а не слоя.

### Когда отбор по государству мимо цели: `@scope class`

`@scope class` — те же две ступени, но первая идёт без условия по `P17`:
вместо обхода по государствам она обходит объявленные классы, по одному
классу за запрос. Это нужно там, где отбор по нынешнему государству теряет
как раз то, ради чего слой собирается. Замеренный случай — `admin_units`:
у исторической единицы деления `P17` указывает на историческое государство
(губерния значится за Российской империей, Российской республикой, РСФСР и
СССР — и ни разу за нынешней Россией), у 223 волостей `P17` нет вовсе, а за
нынешними государствами числятся ровно те объекты, которых слой не ждёт, —
латвийские пагасты и литовские волости.

По одному классу — не из осторожности, а по замеру: девять классов в одном
`VALUES` без опоры на `P17` планировщик начинает с координаты (а `P625` —
это девять миллионов троек) и отдаёт HTTP 504 через 65 секунд; тот же отбор
по одному классу отвечает за 0.6 секунды. Способ годится только узким
классам: сдерживать первую ступень больше нечему, поэтому «губерния» и
«волость» так собираются, а «церковное здание» — нет. Географическим ситом
остаётся рамка РИ/СССР, которую `rows_to_records` проверяет через
`histctx.geo.in_bbox`.
Директива `@owner P127` добавляет ко второй ступени владельца объекта. Просит
его пока один слой — усадьбы: до 1861 года крепостной род ищут через владельца
имения, и без имени слой отвечает «где», но не отвечает «у кого искать». Имя
попадает в поле «Действующее лицо» (`actor`) той же записи — отдельной записи
о человеке не возникает, персоналии проект не собирает. Остальным слоям это
лишнее соединение, поэтому по умолчанию владельца не спрашивают. Имена
сворачиваются подзапросом: у имения бывает несколько владельцев, и обычное
соединение дало бы по строке на каждого, а `dedupe` оставил бы одного — какого
придётся, по порядку ответа сервиса.

Три вещи, без которых сбор снова упрётся в лимиты:

- **`Accept-Encoding: gzip`.** Ответ на десятки тысяч строк сжимается примерно
  вдесятеро. Дело не в трафике: несжатый ответ дольше течёт по сети и успевает
  оборваться на середине — разбор падает на неполном JSON.
- **Пауза между обращениями.** Сервис ограничивает не только время запроса, но
  и частоту: пачка запросов подряд получает
  `429 Aggressively rate-limiting to 1 req / min`, и это состояние держится.
  Пауза (`MIN_INTERVAL_SEC`) считается на весь процесс, отступ после 429 —
  полторы минуты.
- **Дедупликация по Q-номеру.** Многозначные `P31`, `P131` и `P625` множат
  строки: тысяча Q-номеров даёт около двух тысяч строк. Ключ — именно
  Q-номер, а не `uid`: `uid` считается в том числе от координаты, и объект
  с двумя значениями `P625` остался бы на карте дважды.

Бывает, что и двух ступеней мало. Замыкание `wdt:P279*` разворачивается от
класса вниз, к потомкам, и если среди потомков оказался чужой мир — у
«ярмарки» (Q288514) это нынешние выставки и мероприятия, — сервис перебирает
десятки тысяч объектов ради единиц и отдаёт 504 даже по одной России.
Лечится директивой `@filter ?item wdt:P31 ?cls .`: отбор прижимается к
прямому классу, замыкание остаётся в запросе и работает поверх прижатия.
Приём годится там, где класс конечный и подклассов с объектами у него нет.
Это надо именно сверять, а не предполагать: замыкание всегда шире прямого
класса, потому что путь нулевой длины входит в `P279*`. В слое `fairs`
сверено по России и гостиному двору — прямой класс и замыкание дают один и
тот же список из 14 объектов, а весь слой по России собрался в 20 записей
вместо 504. Для церквей или населённых мест так делать нельзя: там подклассы
и есть слой.

Первый запуск слоя — всегда `--probe`: он собирает одну Россию, ничего не
пишет и печатает статистику с примерами. Запрос, который не выполняется или
отдаёт пусто, должен быть виден сразу, а не через сорок минут обхода.

### Переименования: те же две ступени, но свой сборщик

Слой `renamed_places` собирается не движком, а `scripts/harvest_renamed.py`
(разбор — `src/histctx/sources/renamed.py`). Причина в том, где лежит год
переименования: не в значении, а в квалификаторе времени к нему — у заявления
«официальное название» (`P1448`) стоят `P580` и `P582`. Через `wdt:`
квалификаторы не достаются вовсе, нужен полный путь `p:` → `ps:` → `pq:`,
которого вторая ступень движка не умеет. Различие глубже одного пути: движок
делает из строки ответа запись и схлопывает записи по Q-номеру, а здесь из
заявлений одного места строится цепочка названий, и каждое звено становится
отдельной записью со своими годами.

Устройство то же самое и уроки те же: первая ступень дешёвая (места одного
государства, у которых официальное название имеет дату конца), вторая берёт
все названия чанками по 500 через `VALUES`. Класс («населённое место, а не
улица») проверяется на второй ступени: `wdt:P31/wdt:P279*` в первой — ровно
то, из-за чего запрос отдаёт 504, а на списке из пятисот мест тот же вопрос
стоит копейки.
### Приходы: чужая точка, подписи в `extra` и рамка по губерниям

Слой `parishes` (класс «церковный приход», Q102496) собирается тем же
движком, но трём вещам, которых движку не хватало, понадобились директивы.
Все три выключены по умолчанию: запросы остальных слоёв не изменились ни на
символ, по ним считаются `uid`.

**`@place ^P5607 ^P127 P159 P276 P131` — точка, если своей нет.** Своя `P625`
у прихода есть у польских через раз, а у финских почти никогда (у 14 из
592), и без заимствования слой был бы польским и только. Первая ступень при
`@place` координату не требует (`ids_query(..., need_coord=False)`), вторая
спрашивает свою точку, а затем пути по порядку: `^P` — обратная ссылка
(храм сам указывает на приход: P5607 — 4 925 ссылок у 4 039 приходов, P127 —
так заведены финские церкви), прямые — к месту, и только если это населённый
пункт: гмина и община дали бы точку в своей середине. Запись с чужой точкой
помечается `place_level`, путь — в `extra.coord_via`. Итог: своя точка у
5 066 записей из 7 884, P131 — 1 216, P159 — 810, храм по P5607 — 555, по
P127 — 224, P276 — 13; ни той, ни другой нет у 537 из 8 421 — сбор их
пересчитывает и печатает.

У прихода бывает три храма, и сервис отдаёт их в произвольном порядке.
Чтобы точка, а с ней `uid`, не гуляли от сбора к сбору, строки перед
`dedupe` сортируются (`sort_by_place`): своя точка, затем путь по порядку,
затем сама координата строкой.

**`@label P708 diocese` — подписи значений в `extra`.** Епархия и конфессия
(P140) собираются подзапросом, как владельцы усадеб: все значения, кроме
отклонённых, через «; ». Епархия у 3 018 записей из 3 294 в рамке, но она
нынешняя — Кельце, Седльце, Плоцк, — а не епархия XIX века.

**`@frame 1897` — рамка полигонами, а не прямоугольником.** `geo.BBOX_RU` для
нынешней Польши мимо цели в обе стороны: пропускает Краков, Тарнов и Вармию
(Галиция и Пруссия) и режет по 18-му меридиану запад Калишской губернии —
18 приходов. Рамка слоя (`src/histctx/frame.py`) — губернии 1897 года
(`provinces_1897.geojson`, губерния ложится в `region`) плюс из
`state_borders.geojson` за все даты Россия (СССР), Финляндия, Эстония,
Латвия и Литва — земли, бывшие империей или СССР, но не губерниями 1897
года: Львов, Закарпатье, Калининград, Аланды. Межвоенная Польша в список не
входит — с ней пришла бы Галиция. Что вне рамки, остаётся в выгрузке с
пометкой `outside_bbox`.

Россия в CShapes — семнадцать фигур по 21 000 вершин, и перебор рёбер для
4 600 польских точек вне губерний занял на первом сборе 312 секунд. Рёбра
теперь разложены по полосам широты в 0,1° (`frame.Banded`), и вся рамка
считается за секунду. Контуры у моря грубые: финские приходы на островах и
на самом берегу (Ларсмо, Уусикаупунки, Кустави — десять) оказывались в воде.
Точке, не попавшей ни в одно государство, ищется берег на 0,05–0,3°, и
решает первая суша; запись помечается `extra.frame = "по берегу"`. Точку
внутри чужого государства так не двигают: Краков лежит в Австро-Венгрии, а
не в воде. За рамкой по ошибке контуров остались три финских прихода:
Колари и Пелло на Торнио CShapes относит к Швеции, Брендё-Кумлинге лежит
дальше 0,3° от берега.

Итог сбора 24.10.2026: 7 884 записи, в рамке 3 294 (Царство Польское 2 559,
Финляндия 300, прочие губернии 352, вне губерний 83), за рамкой 4 590. Выгрузка —
`data/out/geojson/parishes.geojson`, 6 МБ. Время и прочие замеры — в
шапке `queries/parishes.rq`.

## PastVu: обход клетками и журнал

Сервис отдаёт снимки по прямоугольнику, поэтому страна режется на клетки и
обходится клетка за клеткой. Что важно знать до запуска:

- **Объём.** `--estimate --all` складывает счётчики кластеров и отвечает, не
  выкачивая ни одного снимка (двадцать восемь запросов): 686 000 записей с
  датировкой до 1960 года включительно. Это порядка 400 МБ GeoJSON — прежняя оценка в 200 000 была
  занижена втрое.
- **Шаг.** По умолчанию градус: ограничения на число снимков в ответе у
  сервиса нет (самая плотная клетка, Москва, — около 121 000 снимков и 25 МБ),
  а при полуградусном шаге клеток вчетверо больше и почти все пустые. Весь
  обход — около 7 800 запросов и порядка трёх часов с паузой в полсекунды.
- **Журнал и `--resume`.** Записи ложатся в `data/cache/pastvu` по мере
  обхода, клетка отмечается пройденной только после того, как её записи
  записаны. Оборвался обход — тот же запуск с `--resume` продолжает с места
  обрыва; клетка, на которой была ошибка, пройденной не считается и будет
  собрана заново. Терять трёхчасовой обход из-за одной сетевой ошибки нельзя.
- **Зум.** Отдельные снимки сервис отдаёт с 17-го; ниже он возвращает
  кластеры, и сборщик на таком ответе останавливается — собрать кластеры
  нельзя, а молча собрать пустоту хуже всего.
- **Размер файла.** `data/out/geojson/` в репозитории отслеживается, а GitHub
  не принимает файлы больше 100 МБ: слой целиком туда не положить. Чем резать —
  решать до сбора: `--year-to` сужает период (снимков 1950-х в PastVu больше
  всего), можно собирать по областям отдельными рамками через `--bbox` или
  хранить выгрузку архивом. Сборщик пишет один файл и ничего не решает за
  человека.
### Слои событий обходят больше государств

`@kind event` меняет не только разбор дат, но и сам обход. У здания `P17`
указывает на нынешнюю страну, а у события — на ту, что существовала в момент
события: у восстания декабристов это Российская империя, и на нынешнюю Россию
не ведёт ничего. Поэтому к семнадцати преемникам для слоёв событий
добавляется `HISTORICAL_COUNTRIES` — шесть исторических государств. Проба
по-прежнему берёт одно государство (те же два обращения к сервису), но для
слоёв событий это Российская империя, а не Россия: проба слоя восстаний по
нынешней России показала бы пустоту, которая ничего не значит.

Оттуда же берётся координата. Своей `P625` у события часто нет, есть `P276` —
место события; тогда точка берётся у места, а запись помечается
`confidence = place_level`. Место обязано быть населённым пунктом: `P276`
сплошь и рядом указывает на губернию, а точка в середине губернии выглядит на
карте достоверно и врёт. `P131` не годится по той же причине и целиком
(`docs/SCHEMA.md`).

Слоям событий нужна и верхняя граница по дате — `@filter` по `P580/P582/P585`.
Без неё «катастрофа» и «забастовка» приводят современную хронику: на пробе
бедствий по России из 216 записей до 1961 года оказались 19.

## Погода: приведённый ряд

У метеоданных форматов много, поэтому скачивание и разбор конкретного файла
отделены от расчёта. Любой источник сначала переводится в общий вид — обычный
CSV с такими колонками (имена задаются ключом `--map`, порядок неважен):

| Колонка | Что | Обязательна |
|---|---|---|
| `station_id` | Код станции | да |
| `year`, `month` | Год и месяц наблюдения | да |
| `name` | Название станции | нет |
| `lat`, `lon` | Координаты станции | для точечного слоя |
| `region` | Губерния или область | для слоя по губерниям |
| `tavg` | Средняя температура месяца, °C | одна из двух |
| `prcp` | Сумма осадков за месяц, мм | одна из двух |

Пример перевода из файла с русскими заголовками:

```bash
python3 scripts/harvest_weather.py --probe data/raw/meteo/samara.csv \
    --map "СТАНЦИЯ=station_id,НАЗВАНИЕ=name,ШИРОТА=lat,ДОЛГОТА=lon,\
ГУБЕРНИЯ=region,ГОД=year,МЕС=month,ТЕМП=tavg,ОСАДКИ=prcp"
```

Пропуски в рядах (`-9999`, `9999`, пустая строка) распознаются и не считаются
значениями. Строка с неразобранной датой пропускается, а вот файл без
обязательных колонок останавливает сбор с перечнем того, что в нём нашлось.

### Откуда берётся ряд: GHCN-M

`--fetch` забирает месячные ряды NOAA и сам приводит их к таблице выше —
`--map` для них не нужен. Два набора, идентификатор станции у них общий,
поэтому температура и осадки сходятся в одну строку без сопоставления
по координатам:

| Набор | Что | Как лежит |
|---|---|---|
| GHCN-M v4, температура | Средняя температура месяца, сотые доли °C | `ghcnm.tavg.latest.qcu.tar.gz`, 45 МБ, постоянная ссылка |
| GHCN-M v4, осадки (2024) | Сумма осадков за месяц, десятые доли мм | архив по файлу на станцию, 237 МБ; имя несёт дату сборки, берётся последнее в листинге |

Скачанное остаётся в `data/raw/meteo/` и второй раз не забирается
(`--refresh` перекачивает). В репозиторий эти файлы не идут.

Что делает `--fetch`, кроме скачивания:

- **отбирает станции в границах РИ/СССР** — по коду страны в идентификаторе
  GHCN и по общей рамке охвата. Финляндия и Царство Польское в списке есть:
  до 1917 года это губернии империи;
- **режет ряд по годам** (`--years`, по умолчанию 1800–1960). Это не украшение:
  норма считается по самому ряду, и потепление последних десятилетий сдвинуло
  бы её вверх, а холодные годы XIX века посыпались бы в слой толпой;
- **проставляет губернию** по координате станции — из полигонов переписи
  1897 года (`data/out/boundaries/provinces_1897.geojson`). В GHCN губернии
  нет, а без неё слой `weather_regions` не строится. Если полигонов нет,
  сбор останавливается и говорит, что делать; `--no-regions` собирает
  один точечный слой;
- **не выдумывает названий**: станции в GHCN названы латиницей, так они
  и остаются. Справочника соответствий у нас нет, а придумывать — врать.

Забракованные контролем качества значения не берутся — как и пропуски.
«След осадков» (`-1`) — не пропуск, а ноль с оговоркой: дождь был, измерить
нечего.

Права: данные NOAA/NCEI — общественное достояние (работа правительства США),
ограничений на использование нет; NOAA требует ссылки на набор и гарантий
точности не даёт. У погоды права записываются не в спецификации слоя,
а при сборе, ключом `--license`: ряд может быть любой. `--fetch` печатает
готовую команду `--build` вместе с формулировкой прав и ссылкой на набор.

### Что считается аномалией

В слой идёт не погода, а её отклонения: обычный год — это шум, который на
карте вытеснит собой то, что действительно объясняет факт. Год попадает в
выгрузку, если выполнены **оба** условия:

1. отклонение от нормы не меньше 1.5σ (порог меняется ключом `--threshold`);
2. отклонение велико само по себе — засуха: осадков ≤ 75% нормы; дождливое
   лето: ≥ 130%; суровая зима: ≥ 2 °C ниже нормы; холодное лето: ≥ 1.5 °C
   ниже; жаркое лето: ≥ 1.5 °C выше.

Второе условие нужно из-за первого: в ровном ряду самый сухой год всё равно
окажется «выпадающим» по σ, даже если осадков было меньше всего на четверть.

Норма считается по самому ряду, а не по климатическому периоду 1961–1990:
интерес проекта — 1800–1960 годы, и норма по более поздним данным сдвинула бы
все оценки. Плата за это — ряд короче 15 лет к расчёту не допускается.

Слоёв на выходе два: `weather_stations` — точки станций с годом аномалии,
`weather_regions` — то же, осреднённое по губернии (нужно не меньше двух
станций в губернии). Второй слой существует потому, что до 1880-х годов
станций единицы, а губерния у факта из метрики известна почти всегда.

## Урожай и цены: выгрузка RISTAT

Файловый каталог `ristat.org` не отдаёт файл по постоянному адресу: архив
собирается под запрос, и обойти это нельзя. Сборщик повторяет те же три шага,
что делает человек, — берёт со страницы `form_build_id`, отправляет форму с
отметкой нужной темы и среза и скачивает архив по одноразовой ссылке с
`etl.ristat.org`. Скачанное кладётся в `data/raw/ristat` (в репозиторий не
идёт): пересобирать слой чаще, чем меняются данные, — обычное дело, а дёргать
сайт ради этого незачем.

Берётся русская версия каталога. Английская отдаёт то же самое, но названиями
вроде «Tambov governorate», и их пришлось бы сопоставлять с русскими вручную;
русская выгрузка совпадает с названием губернии из метрической книги как есть.

Значения в выгрузке **уже расшифрованы**: портал применяет к таблице словарь
`Vocabularies RISTAT`, и территория, показатель и единица приходят словами.
Те же наборы в репозитории IISH закрыты — файлы помечены `restricted`, а в
карточке набора сказано, где открыто: «Accessible at http://ristat.org».

Берутся четыре темы за четыре опорных среза (1795, 1858, 1897, 1959; срез
2002 года за пределами окна проекта):

| Тема | Что в ней | Срезы |
|---|---|---|
| `4.01` | Продукция сельского хозяйства в рублях | 1795, 1858, 1897, 1959 |
| `4.02` | Она же в натуре: посев, урожай, поголовье, падёж скота | 1795, 1858, 1897, 1959 |
| `7.03` | Цены на землю, рублей за десятину | 1897 |
| `7.04` | Арендная плата за землю | 1897 |

Срезы 1795 и 1858 годов дают посев и урожай в одних единицах, и сборщик
сводит такую пару в одну запись с отношением **сам-N** — той мерой урожая,
которой мерили современники. Ниже сам-3 после вычета семян на новый сев
остаётся вдвое меньше собранного, и запись прямо называет это недородом:
голое «снято 363 308 четвертей» не объясняет ничего, пока не сказано, много
это или мало. Пара, которую свести нельзя (посеяно ноль, единицы разные, на
показатель несколько строк из разных источников), в одну запись не сливается:
обе строки идут в слой порознь.

Права: выгрузка идёт по CC BY-NC-SA 4.0 — это условие принимается на самом
сайте перед скачиванием, и ссылка на Кесслера и Маркевича обязательна.
Проект некоммерческий, поэтому условие NC не мешает; если это изменится, слой
придётся отключить.
## Засухи по годичным кольцам

Станции начинаются с 1881 года, и дальше этой границы погодные слои не
заглядывают. Голодные годы XVII–XVIII веков объясняют годичные кольца
деревьев: по их ширине восстанавливается летняя засушливость — сеточный
индекс PDSI с датировкой до года. Разбор — `src/histctx/sources/drought.py`,
сбор — `scripts/harvest_drought.py`, тесты — `tests/test_drought.py`.

Наборы NOAA Paleoclimatology, оба — общественное достояние, оба устроены
одинаково: таблица узлов сетки плюс матрица «строка — год, колонка — узел».

| Ключ | Набор | Охват | Годы |
|---|---|---|---|
| `erda` (по умолчанию) | European Russia Drought Atlas, 4259 узлов сетки 0.5° | 22–62° в. д., 41–71.5° с. ш. — до Урала | 1400–2016 |
| `owda` | Old World Drought Atlas | −11.75–44.75° в. д. — Европа и Средиземноморье | 0–2012 |

Основным взят ERDA, хотя в каталоге назван был OWDA: OWDA обрывается на
44.75° в. д., то есть на середине империи, а в общей полосе, по словам самих
авторов, менее точен. OWDA берётся ключом `--dataset owda` ради западной
кромки — Царства Польского западнее 22° в. д., куда ERDA не дотягивается;
матрица его весит 87 МБ, поэтому годы отсеиваются прямо при чтении.

Наборы перекрываются, и в перекрытии одна и та же засуха попала бы в слой
дважды. Поэтому второй набор берётся **только кромкой**: узлы внутри охвата
основного выбрасываются (`--whole` отменяет обрезку), а файл получает своё имя
— `drought_atlas_owda.geojson`. Собрать OWDA поверх ERDA под одним именем
нельзя: это молча подменило бы слой другим, вдвое меньшим. В кромку, кроме
Польши, попадают Балканы и Малая Азия — они внутри рамки проекта
(`histctx.geo.BBOX_RU`), но за пределами империи; рамка одна на все слои, и
отдельного сита у этого слоя нет.

Собранный слой — 26,9 МБ на 28 710 записей: это самый большой файл выгрузки,
и пересобирается он за шесть секунд, а скачанные наборы остаются
в `data/cache/drought/` (в репозиторий кэш не идёт).

### Что считается засухой

Правило то же, что у погоды: в слой идёт не погода, а отклонение от нормы.
Разница одна — считать это отклонение не приходится. PDSI уже нормирован и
уже имеет общепринятую шкалу Палмера: −2 — умеренная засуха, −3 — сильная,
−4 и ниже — экстремальная. Порог по умолчанию — **−4** и меняется ключом
`--threshold`.

Почему не −3, хотя это и есть «сильная засуха»: сетка частая, а засуха —
явление широкое, и при −3 условие выполняется у каждого шестнадцатого
узла-года. Слой перестаёт быть слоем событий и становится полем: 94 248
узлов-лет и 72 602 записи за 1600–1960 годы против 33 019 и 28 710 при −4.
Экстремальная засуха — это тот случай, когда хлеб не родился совсем, и именно
он объясняет запись в метрической книге; кому нужна полная картина, ставит
`--threshold -3`.

Годы по умолчанию — 1600–1960 (`--year-from`, `--year-to`). Нижняя граница —
начало XVII века: раньше личных документов о простых родах почти не остаётся,
и объяснять становится нечего; сам атлас доходит до 1400 года. Соседние сухие
годы сводятся в один эпизод: два сухих года подряд — это один голод, а не два
события, хлеба не стало в первый год, а умирали во второй.

Сверка на известном: лето 1891 года, с которого начался голод в Поволжье,
стоит в наборе как PDSI −4.4 у Самары, −4.0 у Тамбова и −4.2 у Саратова в
следующем, 1892-м. А про голод 1601–1603 годов слой молчит — и правильно: тот
голод случился не от суши, а от холодных дождливых лет, засухи в кольцах за
эти годы нет. Слой отвечает за одну причину из нескольких и чужих на себя не
берёт; остальные — за слоем `weather_chronicles`.

### Узел сетки — не населённое место

Запись остаётся точечной (`scope = point`), но губерния и уезд у неё пустые.
`histctx.geo.extract_region` достаёт губернию из текста, а у координаты текста
нет: приписать узлу «Самарскую губернию» значило бы её выдумать. Подбор по
этому слою идёт по расстоянию, и шаг сетки (около 30×55 км) мельче обычного
радиуса подбора в 50 км — ближайший узел найдётся почти у любого села внутри
охвата атласа. Место в записи названо координатой: «узел сетки 53.75° с. ш.,
50.25° в. д.».

**Покрытие — главное ограничение слоя.** Реконструкция есть там, где растут
долгоживущие деревья и собраны хронологии: густо на западе и в центре, реже
к юго-востоку, и нигде за Уралом — восточная граница ERDA 62° в. д. Для факта
из Тобольска или с Амура слой не даст ничего, и это значит «атлас сюда не
дотянулся», а не «засух не было». Ограничение записано в карточке слоя
(`description`), печатается пробой и сборкой, а узлы на самом краю сетки —
576 из 4259 — помечены `confidence = grid_edge`: с одной стороны от них
хронологий нет вовсе. За Уралом с 24.10.2026 есть третий набор — раздел
«Засухи за пределами ERDA: GEDA».
Первый сбор из GHCN дал 9 678 точек и 1 856 записей по губерниям: 2 587
станций, 729 631 месячное наблюдение за 1800–1960 годы, сто губерний.
Проверка на известном: засуха 1891 года нашлась в Симбирской, Вятской,
Пермской, Курской и Олонецкой губерниях, Уральской и Акмолинской областях;
засуха 1921-го — в Самарской, Симбирской, Вятской, Херсонской, Варшавской и
Приморской. Это те самые голодные годы, и слой указывает на них сам,
без подсказки.

### Сколько станций стоит за губернией

Усреднять по губернии то, что померили в этом месяце, нельзя: состав станций
меняется десятилетиями. В Томской губернии годы с одной-двумя станциями
давали в среднем 188 мм осадков за апрель–август, а годы с двадцатью — 272 мм,
и весь XIX век уходил в «засуху» просто потому, что мерила другая станция.
Поэтому значение станции сначала приводится к общей базе: своя норма меняется
на общегубернскую (температура — разностью, осадки — отношением, потому что
засуха меряется долей от нормы). Отклонение года сохраняется целиком, разница
между местами исчезает.

Остаётся шум: чем меньше станций мерило в год, тем меньше усреднения. Поэтому
в каждой записи стоит число станций **того самого года** (`extra.stations`,
и оно же словами в описании), а год, за который говорит одна станция, помечен
`confidence="thin_coverage"` — таких 530 из 1 856. Из слоя они не выброшены:
до 1880-х годов другой записи по губернии не будет вовсе.

`--probe` на файле со многими станциями считает аномалии по файлу целиком —
это обзор формата, а не результат сбора: состав станций меняется год от года,
и ранние годы выпадают из «нормы» просто потому, что тогда мерила другая
треть страны. В слое норма считается по каждой станции и по каждой губернии
отдельно, и проба об этом предупреждает.

## Засухи за пределами ERDA: GEDA

ERDA кончается на 62° в. д., и за Уралом слой `drought_atlas` молчит. Это
закрывает **Great Eurasian Drought Atlas** (Э. Кук и Б. Кук, Zenodo,
doi:10.5281/zenodo.11059894, CC BY 4.0; статья — Cook et al. 2024, Journal of
Climate, 37: 4389–4401): тот же летний scPDSI на сетке 0.5°, но по всей
Евразии, 1000–2020 годы. Разбор — `src/histctx/sources/drought_geda.py`, сбор —
`scripts/harvest_drought_geda.py`, тесты — `tests/test_drought_geda.py`.
Слой свой, `drought_atlas_geda`, файл — `drought_atlas_geda.geojson`, а не
третий ключ `--dataset` у `harvest_drought.py`: шкала другая (ниже), права
другие (CC BY 4.0 против общественного достояния NOAA), формат другой.
Monsoon Asia Drought Atlas, стоявший на очереди ради юга Сибири, этим
заменён: он обрезан 56-й параллелью и вчетверо реже.

**Формат.** Один файл `geda_trim.nc`, NetCDF4 (то есть HDF5), 226 МБ;
скачивается в `data/raw/geda/` (в репозиторий не идёт), размер и md5
сверяются с карточкой записи на Zenodo. Читает его `h5py` — необязательная
зависимость только этого сборщика, как `geonamescache` у населённых мест
(`pip install h5py`, или `pip install -e .[geda]`); без неё сборщик
останавливается с этой подсказкой, а тесты её не требуют — сито, порог и
записи проверяются на списках. Сверено при первом запуске 24.10.2026: переменная
`scPDSI(yr, lat, lon)` 1021 × 158 × 404, широты 0.25–78.75°, долготы
−21.75…179.75°. Две особенности, без которых разбор ошибся бы молча:

- **Значения — сигмы, а не шкала Палмера.** Атрибут файла: «Trimmed and
  restandardized (zero mean, unit standard deviation; baseline 1000-2020)»,
  единица переменной — `sigma`. Сборщик это сверяет и останавливается, если
  единица другая: порог и шкала словами считаны в сигмах.
- **Море — не NaN, а заполнитель NetCDF 9.97e36.** h5py его не подменяет;
  разбор считает пропуском всё, что по модулю больше 90, — то же правило,
  что у ERDA и OWDA.

**Где берётся.** Только там, где ERDA нет, и только в границах РИ/СССР:

| Узлы рамки проекта (35–82° с. ш., 18–180° в. д.) | Число |
|---|---:|
| без данных — море, озёра | 8 945 |

ERDA внутри своего прямоугольника покрывает сушу целиком — проверено по
узлам: суши у GEDA там ровно 4 259 узлов, и у каждого есть пара в ERDA, —
поэтому граница проводится прямоугольником, как и у OWDA. Территория — это
полигоны России из `state_borders.geojson` (CShapes, `gwcode = 365`): узел
берётся, если центр его клетки лежит в России хотя бы одного из 17 периодов
1886–1960 годов. Так в слой входят Урянхайский край (с 1914 года) и Южный
Сахалин (с 1945-го), а Внешняя Монголия, Маньчжурия и Синьцзян — нет.

Отдельно решено побережье. Полигоны CShapes обобщены, и у 441 клетки, где
GEDA видит сушу, центр лёг в море — по центру они бы выпали, а это 4% слоя:
берег Ледовитого океана, Охотского моря, Камчатка. Поэтому клетка, чей центр
не попал ни в одно государство набора, берётся, если в России лежит хоть один
её угол; клетка с центром в Китае или Монголии не берётся, даже если угол
заходит в Россию (таких на границе 170). 76 узлов западнее 22° в. д. перекрываются с кромкой OWDA
(`harvest_drought.py --dataset owda`) — она в выгрузке не лежит и
собирается только ключом; собирая обе, это надо помнить.

**Порог: −2.5σ.** Порог −4 слоя ERDA к сигмам неприменим. Эквивалент по
частоте — **−2σ**: в общей полосе ERDA и GEDA (4259 узлов, 1600–1960 годы)
PDSI ERDA ≤ −4 выпадает в 2.15% узлов-лет, GEDA ≤ −2σ — в 2.08%. Ниже ступени
шкалы названы по той же редкости (`SIGMA_CLASSES`): −2σ — «экстремальная
засуха», −1.5σ — «сильная» (≈ PDSI ≤ −3), −1σ — «умеренная» (≈ PDSI ≤ −2),
а −2.5σ и ниже — «исключительная». В слое порог строже, −2.5σ:

| Порог | Узлов-лет | Доля | Записей (эпизодов) |
|---|---:|---:|---:|
| −2σ (как ERDA при −4) | 79 663 | 2.02% | 68 057 |
| **−2.5σ (по умолчанию)** | **20 966** | **0.53%** | **19 057** |
| −3σ | 4 860 | 0.12% | 4 579 |

Причин две. Размер: узлов у GEDA за пределами ERDA в два с половиной раза
больше, чем у самого ERDA, и при −2σ записей вышло бы 68 тысяч — в два с
лишним раза больше, чем в самом большом файле выгрузки (ERDA, 28 710 записей,
26,9 МБ); при −2.5σ файл весит 14,5 МБ. И согласие: на общих узлах из узлов-лет, где ERDA даёт
≤ −4, GEDA сам опускается до −2σ только в 15.5% (ниже). На −2.5σ остаётся
то, что выделяется и на фоне этой неуверенности, — в среднем раз в два века
на узел. Кому нужна полная картина — `--threshold -2`. Все записи слоя при
пороге по умолчанию получают одну категорию — «исключительная засуха»; само
значение в сигмах стоит в описании и в `extra.sigma`.

**Согласие с ERDA — главная оговорка слоя.** `--check --compare-erda`
сравнивает два атласа на их общих 4259 узлах. Медианная корреляция годовых
значений по узлам — **0.32** за 1600–1960 годы; за 1990–2016 годы, где оба
опираются на станции, — 0.93 (замер 24.10.2026 отдельным расчётом). Лето
1891 года у Самары: ERDA −4.4, GEDA −1.35σ. Поэтому GEDA не подменяет ERDA
там, где ERDA есть, — несмотря на то, что статья называет GEDA развитием и
улучшением OWDA, MADA и ERDA: у ERDA шкала Палмера и проверка на известных
засухах, у GEDA в Европейской России — нет.

За Уралом сверка с независимыми засухами слоя `weather_regions` (GHCN, 89
губерние-лет восточнее 62° в. д. за 1800–1960 годы): средний индекс GEDA по
узлам губернии в эти годы −0.25σ против 0.00 в остальные, ниже нуля — 63%
против 51%. Сильнее всего совпала засуха 1917 года в Туркестане, с которой
начался голод 1917–1918 годов: Ферганская область −2.86σ, Самаркандская
−2.69σ, Семиреченская −2.60σ в среднем по узлам; 1917 год — шестой в слое по
числу узлов (605). А засуха 1911 года, которую перечень Голубева и Дронина
относит к «восточному» району, у Акмолинска и Тобольска в GEDA не видна
вовсе: там +1.5σ. Вывод записан в карточку слоя (`description`): за Уралом
это лучшее, что есть, но отдельная засуха в отдельном узле — повод
проверить по летописи и метрике, а не установленный факт.

Остальное — как у ERDA: окно 1600–1960 годов (`--year-from`, `--year-to`;
значения после 1989 года в наборе уже инструментальные, в окно они не
попадают), соседние сухие годы сводятся в эпизод, губерния у узла не
ставится, место названо координатой. По векам: XVII — 7 130 записей, XVIII —
5 465, XIX — 4 272, XX — 2 180 (и 10 за 1600 год); больше всего узлов
в 1726, 1637, 1681, 1695 и 1602 годах. Сбор с диска — около 15 секунд.

## Голод 1891–1892 годов по уездам

Набор к статье В. Чарныш лежит на Harvard Dataverse под CC0 1.0 и отдаётся
через API репозитория: список файлов — `/api/datasets/:persistentId/`,
файл — `/api/access/datafile/{id}`, тот же путь, что у heiDATA, только хост
другой. Сборщик `scripts/harvest_famine_1891.py` держит перечень нужных
файлов с идентификаторами и размерами (`FILES` в `sources/famine_1891.py`,
проверено по API 22.10.2026) и на `--check` сверяет его с живым списком:
разошлось — остановка, а не подгонка. Скачанное остаётся в
`data/raw/famine_1891/`, `--build` берёт оттуда. Разбор —
`src/histctx/sources/famine_1891.py`, тесты — `tests/test_famine_1891.py`.

Что надо знать про разбор:

- **Сверка с RISTAT.** Набор пишет губернии и уезды латиницей (`Olonets`,
  `Povenets`). Словари в `sources/famine_1891.py` переводят их по-русски
  (50 губерний и 499 уездов), и каждый уезд ищется среди 824 уездов
  1897 года в `data/out/boundaries/districts_1897.geojson` — внутри своей
  губернии, по ключу `histctx.geo.region_key`, а не по равенству строк.
  Поэтому сбор идёт после `harvest_admin_gis.py --build`: без справочника
  он останавливается. Четырнадцать написаний справочника (Малоярославский,
  Мещонский, Курмыжский, Верхне-днепровский, Соколский, Волковыский,
  Моложский, Великолуцкий, Рославский, Устюжский, Новоградволынский,
  Усть-Медведковский, а также Петроградский и Изяславский — названия 1914
  и 1910 годов, приписанные уездам 1897-го) заведены как написания, а не
  как другие уезды; `Distr_ID` найденной пары кладётся в `extra`. Именно
  `Distr_ID`, а не `RISTAT_ID`: в справочнике `RISTAT_ID` один на всю
  губернию и уезда не различает. До 24.10.2026 в записях стоял он, и все
  уезды одной губернии несли один номер — 49 различных значений на 978
  уездных записей; с `Distr_ID` их 409, у 216 полигонов — 216. Замена
  вскрыла и вторую ошибку: `region_key` отбрасывает номер, и Донской 1-й
  и 2-й округа сводились с одним уездом справочника; ключ уезда
  (`district_key`) теперь номер учитывает. Уезд
  без пары остаётся в данных с `confidence="district_unmatched"` и
  перечисляется в `--check`; в наборе таких не оказалось — нашлись все
  216 уездов главной таблицы и все 499 уездов панели. Списки уездов
  1891 и 1897 годов могут расходиться — такое записывается, а не
  исправляется.
- **Месяцы помощи.** Четырнадцать колонок `OnReliefJuly1891 … OnReliefAug1892`
  — число людей на помощи по месяцам. Период записи — с первого по
  последний месяц с ненулевым числом, точность `month`, `period_raw`
  словами («ноябрь 1891 — июль 1892»). Авторские `onset_mo` и
  `endrelief_mo` считают месяцы с июля 1891 года (июль = 1, август 1892 =
  14) и начинают кампанию с месяца, когда на помощи больше 1% населения, —
  так сказано в статье и так сходится по данным у 170 уездов из 175; в
  разбор они идут только сверкой. Месяцы календарные, стиль календаря
  источник не оговаривает — ничего не пересчитывается.
- **Категория по факту помощи:** `OnReliefTot > 0` — «помощь выдавалась»,
  `= 0` — «без продовольственной помощи», пусто — «о помощи данных нет».
  Пустые колонки у всех уездов Калужской и Харьковской губерний и у четырёх
  Курской; нули у пятнадцати уездов, и у одиннадцати из них при нулях в
  помесячных колонках всё же выданы ссуды семенами и хлебом — запись это
  говорит, категория остаётся по правилу. Пик помощи — максимум по
  месяцам, доля — `onrelief_max.x` (она же максимум к `TotPop`).
- **Двойная кодировка.** Названия губерний в `Province_Mortality.tab`
  прошли через latin-1 и выглядят как `Ð¡Ð°Ñ€Ð°Ñ‚Ð¾Ð²Ñ\x81ÐºaÑ\x8f`;
  восстанавливаются обратным проходом (`encode("latin-1").decode("utf-8")`),
  и чистить строку до этого нельзя — внутри неё NEL и неразрывный пробел,
  которые `clean_text` принял бы за пробелы. У Саратовской внутри
  кириллицы стоит латинская «a», она заменяется; «Астрахань» записана не
  прилагательным. Результат сверяется с `prov_RU` из
  `provinces_1897.geojson`: 24 из 24, в том числе Астраханская и
  Тобольская, которых в главной таблице нет. Исходная строка остаётся в
  `extra["province_raw"]` escape-записью: NEL внутри значения ломал бы
  построчное чтение выгрузки.
- **Полигоны.** `DistrictMap.shp` — 566 уездов, из них в подложку идут 216
  главной таблицы (поле `ter_id` ↔ `ter_ID`):
  `boundaries/famine_1891_districts.geojson`, 1,0 МБ при шести знаках в
  координатах — втрое меньше `districts_1897.geojson`, округлять не
  пришлось. Свойства: `ter_id`, уезд и губерния по-русски, `Distr_ID`,
  категория, доля на помощи в пике, месяцы и период помощи, ссуды в пудах,
  население.
- **Чего в тексте нет.** Урожаи (`HarvestMean*`), остатки хлеба
  (`Ostatok*`), оклады (`oklady*`), индексы Майерса и Уиппла,
  сверхсмертность по губерниям (`ExcessMortalityV1/V2`): единица в статье
  не названа, числа лежат в `extra["famine"]` под именами колонок.
- **Панель 1885–1896 годов.** `time-series-dataset.tab` (499 уездов
  50 губерний × 12 лет, 5 988 строк, id 5590302) даёт ещё два вида
  записей. Холера: `cholera_cases` и `cholera_deaths` заполнены только за
  1892 год; запись получает уезд с умершими > 0 — 343 из 499, всего
  153 261 умерший, — с числом заболевших, умерших и долей умерших от
  холеры во всех смертях уезда за год. Сверхсмертность: `est_em` — это
  `est_cdr − cdr_pred`, смертей на тысячу населения сверх ожидаемого;
  тождество проверяется на строках до того, как единица попадёт в текст
  (сходится до 1e-8 на 5 978 строках, разошлось бы — сбор встал).
- **Порог сверхсмертности.** Запись «уезд-год» создаётся по правилу слоя
  погоды: `est_em ≥ 1,5σ`, где σ — выборочное стандартное отклонение
  `est_em` по всей панели, а не по прошедшим порог строкам. По панели
  22.10.2026: σ = 4,738 на тысячу, порог 7,107; по нему 419 записей, из
  них 139 за 1892 год и 61 за 1891-й. Порог считается кодом и печатается
  в `--check` и в описании каждой записи (`extra["excess_threshold"]`).
  Поле `work` у записей панели — только за 1891–1893 годы (неурожай и
  два года, которые статья считает голодными, `famine2`): сверхсмертность
  1885 года в Лифляндии с голодом 1891 года не сводится. Колонки `relief`,
  `famine`, `famine2` — переменные регрессии статьи, а не факты
  (`famine = 1` у всех 499 уездов 1892 года): в категорию не идут,
  в `extra` остаются.
- **Словари панели.** Губерний в панели 50, уездов 499; словари
  `PROVINCES` и `DISTRICTS` покрывают их целиком, а Область Войска
  Донского — отдельным словарём по губернии и уезду: её единицы —
  округа, и «Rostov» там не то же, что Ростовский уезд Ярославской
  губернии. У RISTAT эта область зовётся «Земля войска Донского» —
  сверка знает об этом.

## Районы УССР и перепись 1926 года: HURI MAPA

Сборщик — `scripts/harvest_huri.py`, разбор — `src/histctx/sources/huri.py`,
тесты — `tests/test_huri.py`. Источник — открытый ArcGIS REST атласа MAPA
(`maps-huri-ws.net/arcgis/rest/services`): MapServer с разрешённым Query,
`maxRecordCount` 1 000, ответ JSON. Объекты забираются страницами
(`resultOffset`) с явным `orderByFields=OBJECTID` — без порядка смещение
вправе пропустить или повторить объект — и сразу в WGS 84 (`outSR=4326`);
родная проекция сервиса — EPSG:5563. `robots.txt` на сервере нет (404).
Что решено по данным, проход 24.10.2026:

- **Перечень в коде.** 28 слоёв `master_admin` (номер, имя, дата среза,
  уровень, число объектов), имя и поля слоя переписи и слоя Подолии записаны
  в `SLICES` и `REQUIRED_*`; `--check` сверяет их с сервером, и расхождение
  останавливает сбор. Полей два набора: у среза 25 октября 1932 года они
  свои (`NAME_UA`, `NAME_RUS`, `NAME_LAT`, `TYPE`, `DATE`, `COMMENT`,
  `Master_rai`) — разбор сводит оба к одним именам свойств.
- **Срезы и даты.** Группа слоёв названа «1928-04-15», а слои и даты начала
  в них — 15 августа 1928 года: срез датируется по слоям. Срез «1 April
  1933» — копия среза 15 декабря 1933 года до вершины (атрибуты, даты и
  геометрия совпадают у всех трёх его слоёв); он не выгружается, а
  `--check` проверяет, что копия осталась копией: появятся на сервере свои
  данные на 1 апреля — сбор встанет. У 102 центров повитов января 1922 года
  даты 1928–1932 годов: они не переписаны, а помечены `dates_conflict`;
  срез объекта — в `as_of`. У центров 25 октября 1932 года дат нет вовсе.
  Даты читаются из миллисекунд UTC, все приходятся на полночь.
- **Упрощение.** Полигонов 3 571, вершин на сервере 1 502 754 — из них
  1 192 082 у трёх подробных срезов (1922, 1927, 1928); срезы 1932–1937
  годов уже обобщены (около сотни вершин на район). Дуглас — Пекер с
  допуском 0,001° (около 70–110 м) и округление до 4 знаков оставляют
  459 612 вершин и 9,3 МБ файла. Замер одной геометрии: при 0,0005° —
  10,9 МБ, при 0,001° — 8,2, при 0,002° — 6,0. Кольцо, которое упрощение схлопнуло бы, берётся без
  упрощения: район не пропадает. Кольца переориентируются под RFC 7946,
  дыры приписываются внешнему кольцу, в котором лежат.
- **Перепись: какой слой.** Девять слоёв `master_ethnic` несут одну и ту же
  таблицу и различаются раскраской (проверено: атрибуты слоёв 0 и 8
  совпадают); берётся слой 8 без геометрии — полигоны те же, что у районов
  1 марта 1927 года, и по ключу `RAY_Master` + `UKR_Name` берутся оттуда.
  Ключ двойной: `Ray-1927-01-31` в источнике носят два района,
  Новоселовский и Мангушский.
- **Перепись: числа.** У цыган, чехов, болгар и латышей колонки строковые,
  с разделителем тысяч («1,596») — читаются как числа. «Всего» больше суммы
  четырнадцати народностей на 5–3 117 человек (прочие народности): остаток
  не выдумывается. Колонка доли расходится с числами только у чехов (38
  районов); доли в тексте считаются по числам. Три единицы с нулями
  (Киевский и Одесский горсоветы, Плавни) остаются записями с категорией
  «числа не заполнены». Сумма по таблице 25 886 241.
- **Перепись: губерния и округ.** Губерния 1897 года — по точке внутри
  полигона района (середина самого широкого отрезка горизонтали через
  середину кольца: центроид подковы бывает вне района) и полигонам
  `provinces_1897.geojson`: нашлась у 625 из 625. Не нашлась бы — запись
  осталась бы с `confidence="region_unmatched"`. Округ по-русски — из слоя
  округов того же среза; три округа (Мариупольский, Мелитопольский,
  Сталинский) колонка `REGION` у районов пишет иначе, чем слой округов, и
  находятся по его `LABEL`. Две опечатки русских названий в слое округов
  исправлены словарём `OKRUHA_RU_FIXES` («Харковский», «Бердичевкий»).
- **Подолия.** Координата — в полях `y_Latitude`/`x_Longitude`: геометрии
  слой не отдаёт. `date_start`–`date_end` — датировка первого упоминания
  («1411–1430» — документ этих лет), а не годы жизни места; без начала —
  «не позже» конца. Село, город и присёлок с нынешним названием тянутся
  до 1960 года открытым сроком (477); пустошь, урочище, лес, замок, городище

## Голод 1932–1933 годов по районам

Два набора. Пакет воспроизведения А. Маркевича, Н. Науменко, Н. Цянь
лежит на Zenodo архивом `v3.zip` («Other (Attribution)»): внутри каждая
таблица в `.dta` и `.xlsx`, код Stata и `readme.pdf` с источниками по
годам. Таблицы читаются из `.dta` через pandas — он уже в зависимостях, а
`.dta` вдвое меньше и хранит типы. Набор A. Rozenas, Y. Zhukov лежит на
Harvard Dataverse под CC0 1.0; нужен один файл — `main_data.Rdata`.
Сборщик `scripts/harvest_famine_1933.py` держит размер и контрольную сумму
обоих файлов и размеры трёх таблиц внутри архива (`ARCHIVE`, `MEMBERS`,
`RZ_MAIN` в `sources/famine_1933.py`, проверено 24.10.2026) и на `--check`
сверяет их с живыми перечнями: разошлось — остановка; в записи Zenodo
появится архив новее `v3.zip` — тоже остановка. Разбор —
`src/histctx/sources/famine_1933.py`, файлы R — `sources/rserial.py`,
тесты — `tests/test_famine_1933.py` и `tests/test_rserial.py`.

Что надо знать про разбор:

- **Файл R без R.** `main_data.Rdata` — сериализация R (XDR, `RDX2`), в
  ней объект `SpatialPolygonsDataFrame` пакета `sp`: таблица на 995 колонок
  и 386 полигонов. Пакет `rdata` с PyPI это читает, но тянет xarray и свой
  pandas; формат простой, и `rserial.py` разбирает его стандартной
  библиотекой — как `shapefile.py` и `geopackage.py` свои форматы. Сверено
  с `rdata` 1.1 на этом файле: все 995 колонок совпали до значения,
  полигонов 386, вершин 109 436. Матрица координат R хранится по
  столбцам — сначала долготы, потом широты; дырки отдаются своему
  внешнему кольцу по пометке `comment` пакета `sp`. Порядок полигонов
  совпадает с порядком строк, и `ID` полигона сверяется с колонкой `ID`:
  съедет — сбор встанет.
- **Что такое `FAMINE_*`.** Кодбука в наборе нет; ответ — в статье
  (APSR 2019, с. 7, сноска 5) и приложении (разд. 4.1): оценки
  сверхсмертности из атласа MAPA Украинского научного института Гарварда
  (Wolowyna et al. 2016, «Regional variations of 1932–34 famine losses in
  Ukraine»), пересчитанные авторами в районы 1933 года. Доля потерь у
  авторов — `FAMINE_TOTAL / (FAMINE_TOTAL + POP1933_TOTAL)`
  (`Replication.R`, строка 39); в описании записи она так и названа. Годы
  записи — 1932–1934, по названию работы Wolowyna и др.
- **Тождество сверхсмертности пакета.** `excess_mortality_1933` — ровно
  `mortality` 1933 года минус `mortality` 1928-го, а `mortality` — умерших
  на жителя (в коде пакета `mortality = dead / pop`). Проверяется на
  строках до того, как разница попадёт в текст «на столько-то на тысячу
  больше»: 1 752 района, расхождение до 1,2e-8 (колонки во float32);
  разойдётся больше чем на 1e-6 — сбор встанет. Доли float32 округляются
  до семи значащих цифр — дальше в них шум.
- **Точка — центроид.** Полигонов районов 1934 года в пакете нет, есть
  `xcoord`/`ycoord` — центр района. Запись ставится в эту точку, но
  помечается `confidence = district_centroid`, а в `extra["point"]`
  сказано словами, что это место района, а не события. То же у районов
  Rozenas, Zhukov: их точка — `labpt` полигона (колонки `LONG`/`LAT`).
  Губерния 1897 года по центроиду ищется по `provinces_1897.geojson` тем же
  лучом, что губерния станции погоды (`ghcn.Provinces`), — найдена у 2 017
  районов из 2 020.
- **Неполный учёт смертей.** Меньше пяти умерших на тысячу за год не
  бывает ни у какого населения той эпохи; в среднем по районам 1928 года
  — 19. Такое число — неполная регистрация, и запись получает
  `confidence = registration_gap` и оговорку в описании, а не выбрасывается.
  Ниже порога 23 района, 16 из них — Дагестан, который и статья держит вне
  основной выборки (`main_sample = 0`, лежит в `extra`).
- **Категории районов:** смертность 1933 года выше 1928-го (1 386), не
  выше (366), только за 1933 год (188), за 1933 год смертности нет (80).
  Записи без чисел остаются: район в наборе — уже факт.
- **Названия.** Районы пакета — по-русски прилагательным («Бершадский»):
  к ним добавляется «район», сокращения набора раскрываются («гс» —
  горсовет, «нац окр» — национальный округ), прочее остаётся как есть.
  Регионы пакета названы по 1932 году кратко («Украина», «ЦЧО») — словарь
  `REGIONS` даёт полное название в том написании, что у кураторского
  события famine_1932. Районы набора Rozenas, Zhukov — по-украински, как в
  источнике; область переводится по-русски словарём `UKR_OBLASTS`.
- **Сверка двух наборов.** Центроид района пакета ищется в полигоне
  района 1933 года. 386 из 392 районов УССР пакета легли в полигон; шесть
  вне — районы Молдавской АССР, которые набор Rozenas, Zhukov исключает.
  Границы 1933 и 1934 годов не совпадают, и центроид иногда ложится к
  соседу; второй проход отдаёт району 1933 года без пары район пакета с тем
  же грубым ключом названия (первые три согласных после сведения
  украинских букв к русским) из полигона, куда легли несколько, — если
  кандидат один. Итог: пара у 384 районов из 386, один к одному у 382 (у
  358 из них совпал и ключ названия), вторым проходом — 4; без пары
  Ситковецький и Старо-Микольський (Володарський), а Люксембурзький район и
  Запорізька міськрада получили по два района пакета. Пара лежит в
  `extra["rz_rayon"]` с пометкой `matched_by` и в
  `extra["mnq_district_ids"]` записи района 1933 года.
- **Спорное во втором наборе.** Сумма `POP1933_TOTAL` по районам — 38,9 млн
  при 31,4 млн у всей УССР 1933 года по таблице `provinces` пакета:
  пересчёт в районы 1933 года где-то считает дважды. `FAMINE_TOTAL` не
  равно `FAMINE_URBAN + FAMINE_RURAL` у 362 районов из 386 (на сотни
  человек). `ID_2_1933` повторяется у двух пар разных районов, поэтому
  ключ — `ID`. Ничего не исправляется: все числа лежат в `extra` под
  исходными именами.
- **Регионы.** Таблица `provinces` — 27 регионов в границах 1932 года;
  умершие `dead` есть за 1923–1940 годы (439 значений), население — только
  за годы переписей и 1933-й. Запись по региону — без точки, годы
  1932–1933, ряд умерших целиком в `extra`; в описании — 1928, 1932, 1933
  и 1934 годы и во сколько раз 1933-й больше 1928-го.
- **Губернии 1871–1914 (`mortality_1871_1914`).** Таблица `czar` — 50
  губерний × 44 года, умершие есть в 1 914 строках. Три строки с нулём
  умерших (Гродненская и Воронежская 1871, Минская 1879) — пропуск, а не ноль
  смертей: в тренд не идут и печатаются в `--check`. Смертность на тысячу
  сравнивается с линейным трендом своей губернии за все годы — она падала
  с 37 до 27 на тысячу, и без тренда начало периода выглядело бы сплошной
  сверхсмертностью. Порог — полторы сигмы превышения по всей панели, как у
  погоды и панели Чарныш: σ = 3,852, порог 5,778 на тысячу, 112 записей,
  больше всего за 1892 (18), 1882 (13) и 1872 (11) годы. Губернии
  записаны транслитом RISTAT с приписками вроде `after1851`; словарь
  `CZAR_PROVINCES` переводит их, `famine_1891.ProvinceIndex` сверяет с
  губерниями 1897 года — 50 из 50. Сбор хлебов `grain` остаётся в `extra`:
  единицу readme не называет. Пермская губерния 1913 года (79 на тысячу
  при 42 по тренду) стоит особняком — эпидемии за этот год источник не
  называет, запись оставлена как есть.
## Волнения, реформы, мобилизация и города: три пакета Dataverse

Три пакета воспроизведения на Harvard Dataverse, все под CC0 1.0, идут тем
же путём, что и голод 1891 года; общая часть — перечень файлов, сверка и
кэш — в `src/histctx/sources/dataverse.py`. Перечень каждого пакета (id,
имя, размер, у ингестированных таблиц — размер исходника) записан в коде и
сверяется на `--check` вместе с лицензией: разошлось — остановка.
Ингестированные таблицы берутся исходником (`?format=original`, `.dta`):
TSV-копия Dataverse теряет подписи колонок, а других описаний переменных в
пакетах нет. `.dta` читает `pandas.read_stata`.

**Уезды латиницей.** Сведение с 824 уездами 1897 года
(`districts_1897.geojson`) — `src/histctx/sources/uezd_names.py`. Ключ
снимает различия транслитераций («kh»/«h», «ts»/«c», «ia»/«ja»/«ya»,
«i»/«j»/«y», двойные буквы, окончание прилагательного; у пакета о
мобилизации «w» — это «щ») и считается с обеих сторон: от латиницы пакета и
от `Name_ENG` и `Name_RU` справочника. Сравнение — только внутри губернии.
Порядок: точное совпадение ключа; начало названия, если такой уезд в
губернии один (пакет обрезал «2. Aleksandr»); `difflib` не ниже 0,8 с
запасом 0,05 над вторым кандидатом; ручной словарь опечаток и
переименований (`NAFZIGER_DISTRICTS`, `DISTRICTS_MANUAL`). Не сошлось —
`district_unmatched`. Уезд опознаётся по `Distr_ID`: `RISTAT_ID` в
справочнике один на губернию (у всех девяти уездов Архангельской —
«1897_04») и уезда не различает.

**Волнения 1851–1871 годов (`peasant_unrest_1851`).** `event_data_replication.dta`

Род действия — по букве кода: `ar` — отказ (2 665), `at` — захват и насилие
(1 085), `ac` — жалоба (420), `ag` — смена управления (52); событие с
несколькими родами считается в каждом. Подписей в пакете нет, расшифровка —
по статье FGO 2015 (CPS) и совпадению частот, кодовая книга (онлайн-приложение
журнала) из среды недоступна. `large = 1` — событие охватило несколько
селений или уездов (968 записей «уезд-год» с таким событием получают
категорию «охватили несколько селений или уездов»), `a_tsgaor = 1` —
источник в ЦГАОР. 39 строк без `a` (только `at20`) статья не считает; здесь
они остаются, а текст их называет. Динабургский уезд (12 событий) есть
только в таблице уездов пакета и без губернии — он Витебский, как и в коде
статьи (`merge_replication.do`).

**Уезд после реформ (`reforms_uezd`).** Из 344 колонок
`variables_replication.dta` в текст идут 30, по шести сюжетам; колонки
сюжета лежат в `extra["columns"]`. Проверено по данным до того, как числа
попали в текст: `serfperc1` = (крепостные мужчины + женщины 1857 года) /
население по Бушену — сходится у 481 уезда из 482, расходится у Витебского,
и это объясняет поправка 2019 года (`Note.pdf`: Суражский и Витебский
посчитаны вместе); `peasantrepresentation_1864` = места третьей курии /
сумма трёх курий × 100 — до 4·10⁻⁶ на 365 уездах; крепостные 1859 года
(дворовые + барщина + оброк) равны крепостным мужского пола 1857 года
(медиана отношения 0,996) — поэтому доли барщины и оброка в тексте названы
долями «крепостных мужского пола». Суммы расходов земства 1883 года в текст
не идут — единицу пакет не называет, — только доли образования и медицины в
общих расходах; у двух уездов расход на образование или медицину больше
всех расходов, такие доли не пересказываются. `percenrolledm1880` (до 73,9%) — неясно, к чему
отнесена доля, в текст не идёт. Не взяты: почвы (`pctsoil*`), расстояния,
оценки и остатки регрессий (`ahat_*`, `aresid_*`), дворянское
землевладение 1877 года по разрядам, недоимки и оклады 1895 года,
монастыри по указам 1764–1795 годов — переменные модели или сюжеты, которым
нужен свой разбор. Пометка составителей к населению 1858 года
(`bushendataissues1858`, 29 уездов) лежит в `extra`, текст на неё
ссылается.

**Мобилизация 1914–1916 годов (`mobilization_1914`).** `LMMM_district_farmtype.dta`
— 763 уезда × 2 типа хозяйств × 3 года. `mobiliz2` (тыс. призванных)
заполнена в строках 1916 года, одна на уезд; знаменатель — `rpop1912`
(сельское население 1912 года, тыс.). Доля призванных пересказывается, если
она от 0 до 30%: медиана 8,2%, отрицательна у 25 уездов, больше 30% — у трёх
(Никольск-Уссурийский 63%, Медвеженский и Святокрестовский уезды
Ставропольской губернии — больше 100%);
эти 28 записей получают категорию «оценка неправдоподобна». У 177 уездов
`mobiliz2` пуста — запись остаётся с посевами. Посевы (`agrains`, тыс. га,
рожь, пшеница, овёс, ячмень) — сумма общинных и частных хозяйств, только
когда заполнены обе строки года. Губерния пакета переводится по первому
слову названия через ключ к `prov_RU` справочника (87 из 94), остальные
семь — ручным словарём (Батумская область, Сухумский и Закатальский округа,
Камчатская и Сахалинская области, Санкт-Петербургская губерния, Область
Войска Донского).

**Население городов (`city_population`).** Из архива пакета (26,6 МБ, один
файл в наборе) читается `data/city_pop_panel.dta` — в память, без
распаковки. Население — `exp(log_pop)` с округлением до человека; сверка с
`city_pop_cross_section.dta` (целые числа 1897 года): 364 из 366 городов
нашлись по координате, 363 совпали до человека. Записи — только срезы до
1959 года включительно; 15 городов, у которых население есть лишь с 1970
года, записей не дают. Название — сведением с GeoNames по координате
(пакет координату пишет с двумя знаками, это до километра): место в 10 км с
корнем названия уезда — `uezd_town` (185 городов), иначе ближайшее не дальше
3 км — `nearest` (451), дальше 3 км — `uncertain` (27), ничего в 10 км —
`none` (5). Пороги выбраны по выборке: у губернских и уездных городов
ближайшее место GeoNames лежит в 0,2–2,5 км, а у Ярославля точка пакета
отстоит от города на 6,4 км и ближайшим оказывается Гаврилов-Ям — такой
случай и должен остаться без названия. Русское имя — из
`alternatenames/XX.zip` GeoNames (страны — по слою `settlements`: Россия,
Украина, Эстония): `ru`, «основное» и не «краткое», не разговорное и не
историческое; у 1 267 мест из 1 276 оно есть, у остальных в заголовке
латинское имя GeoNames. Заголовок точки слоя `settlements` для этого не
годится: это первое кириллическое из альтернативных названий без языка
(«Маскав» у Москвы, «Казан», «Бетъырбух»). Исторические русские имена идут
в описание; годы у них берутся свои или английского двойника с тем же
ключом (Tsaritsyn 1589–1925), и название, действовавшее в год записи,
ставится в заголовок: 13 записей вроде «Сталинград (ныне Волгоград)».
Срезы 1970–2002 годов лежат в `extra["population"]`.
## Оккупация и освобождение городов

Справочник «Освобождение городов» (М.: Воениздат, 1985) выложен на soldat.ru
полным текстом; раздел СССР — шесть страниц `1-ssr-1.html` … `1-ssr-6.html`

Архив `osv-gorod.zip` (402 КБ) — это документ Word 97 `osv-gorod.doc`: без

## Сожжённые деревни Белоруссии 1941–1944 годов

Слой `burned_villages_by` собирается из двух источников. Основа — набор
Ю. Жукова к статье о карательных операциях в оккупированной Белоруссии
(World Politics, 2017) на Harvard Dataverse, CC0 1.0: файлы отдаются тем же
путём, что набор Чарныш, — список по `/api/datasets/:persistentId/`, файл по
`/api/access/datafile/{id}`. Дополнение — карточки базы НАРБ на `db.narb.by`:
права не выяснены, берутся факты и ссылка на карточку. Сборщик —
`scripts/harvest_burned_villages.py`, разбор — `src/histctx/sources/burned_villages.py`,

Что решено по данным (замеры 24.10.2026):

- **Перечень файлов.** Нужны два из 68: `BELARUS_VILLAGES_Full.tab`
  (id 2972130, 4 988 615 байт) и `BELARUS_VILLAGES_MONTHS_Full.tab`
  (id 2972087, 291 306 706 байт). Идентификаторы и размеры записаны в коде и
  сверяются с API на `--check`: разошлось — остановка.
- **Помесячный файл — потоком.** 380 595 строк, 110 колонок, 48 месяцев с
  июня 1941 по май 1945 года. Он читается прямо из ответа сервера, построчно;
  на диск ложится выжимка `months_scan.json` — 9 090 строк «деревня-месяц»
  с ненулевыми дворами, погибшими или акциями. Проход занимает около десяти
  секунд; `--refresh` повторяет его, иначе берётся выжимка.
- **Сверка месяцев с итогами.** Суммы по месяцам должны совпасть с
  `HOUSES_DESTROYED`, `PEOPLE_KILLED` и `REPRISAL` главной таблицы у каждой
  деревни, иначе сбор останавливается. Не совпадали у одной — Заболотье
  (VID 2217): у неё 51 строка вместо 48, две строки января 1944 года
  записаны дважды. Буквальные повторы строки «деревня-месяц» схлопываются
  (2 строки), и суммы сходятся у всех 7 929.
- **Кодировка.** Названия в помесячном файле — UTF-8, прочитанный как
  latin-1 («ÐÐ±Ð°ÐºÑÐ¼Ñ»), как губернии у голода 1891 года;
  обратный проход `encode("latin-1").decode("utf-8")` восстанавливает все
  7 929 и сверяется с главной таблицей по ключу без знаков препинания. В
  записи идут названия главной таблицы. Три названия с кавычками внутри
  («Льнозавод "КИМ"», «Рыбхоз "Белое"», «Тимоново (центр с-за
  "Тимоново")») ингест записал с обратной косой чертой и лишними
  кавычками — они выправляются.
- **Период.** Месяцы, где у деревни есть акция (`REPRISAL > 0`; дворы и
  погибшие без акции не встречаются ни разу): 7 303 деревни — один месяц,
  506 — два, остальные 107 — от трёх до 32 месяцев; в `period_raw` до
  четырёх месяцев перечисляются, дальше — «с … по …, N месяцев». Точность —
  месяц. 13 деревень без единого ненулевого месяца (и итоги у них нулевые)
  остаются с периодом 1941–1944 и точностью «год». По году начала: 1941 —
  287, 1942 — 1 253, 1943 — 5 005, 1944 — 1 371.
- **`HOUSES_PRE` и `PEOPLE_PRE` — величины района.** Колонки названы как
  дворы и жители до войны, и журнал дискавери сначала так их и записал. Но
  у всех деревень одного `RAYON_ID` они одинаковы (170 районов из 170), а
  `HOUSES_PROP` ровно равно `HOUSES_DESTROYED / HOUSES_PRE`: это
  знаменатель статьи по району. В запись не идут; дворы и жители деревни до
  войны даёт карточка НАРБ.
- **Координата — не всегда деревня.** 7 929 деревень стоят в 4 175 точках.
  В одной точке у Руденска — 325 деревень Воложинского, Ивенецкого,
  Смолевичского и других районов, в Освее — 231, в Витебске — 159;
  одноимённые деревни разных районов («Адамово» Сенненского и Освейского)
  делят одну точку. Правило: точка остаётся за деревней, если в ней нет
  другой деревни с другим названием или из другого довоенного района
  (`point_mates`; название сравнивается по ключу без знаков, «ё» и типа
  поселения после запятой — «Староселье, пос.» и «Староселье» одно; две
  «Байдино» Россонского района в одной точке — одна деревня двумя
  строками, точка за ними сохраняется). Так точкой встают
  3 552 деревни; 4 377 идут без точки, с охватом «район в области»
  (`scope = region`, `regions` — довоенная область) и
  `confidence="shared_point"`, а координата набора и число соседей по точке
  лежат в `extra`. Из 3 396 деревень, стоящих в точке поодиночке, у
  района которых есть медиана (не меньше пяти таких точек), 2 722 лежат
  ближе 30 км от медианы своего района, 362 — дальше 60 км: правило ловит
  общие точки, а не любую ошибку геокодера.
- **Район «до войны».** `RAYON_PREWAR` у части деревень — нынешний район, а
  не довоенный: у «Абразеево» VID 3 стоит Верхнедвинский (район создан в
  1962 году на месте Дриссенского), в карточке НАРБ та же деревня —
  Освейского района. Поле записи `district` берётся из набора как есть;
  сведение с НАРБ сравнивает его и с довоенным, и с нынешним районом
  карточки.
- **Группа и связь со сражениями.** Группа `military`, поле `work` —
  «Великая Отечественная война 1941–1945», как у слоя сражений.

База НАРБ:

- **Что можно запрашивать.** `robots.txt` закрывает `/wp-json/` (REST
  WordPress, где лежат 9 416 карточек), `/search`, `/page/` и любые адреса
  с параметрами (`/*?`). Сборщик читает `robots.txt` первым запросом и
  проверяет по нему каждый адрес; адрес с `?` отбрасывается сам —
  `urllib.robotparser` подстановок не понимает. Адреса карточек берутся из
  `sitemap_index.xml` → `village-sitemap*.xml`: 10 файлов, 9 416 ссылок,
  из них 9 288 разных (128 карточек повторяются в двух файлах).
- **Подпись — и почему НАРБ пока не собирается.** Сетевой фильтр сайта
  обрывает соединение, если в User-Agent есть слово «harvesting»: с общей
  подписью `net.USER_AGENT` не прошёл ни один запрос, с той же подписью без
  пояснения в скобках — все. Это отказ сайта сборщикам, а не сбой, и
  подгонять подпись под фильтр — тот же обход запрета, что и закрытый путь
  в `robots.txt`. Сборщик ходит с общей подписью, поэтому `--probe` и
  `--narb-all` до договорённости с архивом (info@mail.narb.by) ничего не
  скачивают, а слой собирается из одного набора Жукова. Числа пробы ниже
  получены 24.10.2026 с подправленной подписью, до этого решения; карточки
  той пробы в выгрузку не вошли.
- **Обрывы.** Соединение рвётся примерно на каждом третьем-пятом запросе
  (на пробе 40 карточек — 8 обрывов на 60 запросов). Клиент повторяет до
  восьми раз с паузой, растущей на секунду с каждой попыткой; HTTP 4xx не
  повторяется. Средний темп с паузой в секунду — 4–7 секунд на карточку,
  полный обход 9 288 карточек — 10–17 часов. Разобранные карточки
  дописываются в `narb_cards.jsonl` построчно (только факты, без HTML), и
  `--narb-all` продолжает с места; оборванная последняя строка при чтении
  пропускается.
- **Что берётся из карточки.** Название, область и район до войны и
  нынешние, год и дата уничтожения, дворы и жители до войны, сожжённые
  дворы и убитые, «Поисковые данные» — архивные шифры и ссылки на книги
  «Память», «Судьба деревни», «Заметки». Дата бывает одна («октябрь
  1943 г.», «5 марта 1943 г.»; опечатка «мац» читается как май) и
  несколько («1942 г., август 1943 г.», «февраль, май, сентябрь 1943 г.» —
  месяц без года берёт год справа): читаются все, у записи без пары
  интервал — от первого года до последнего. «Судьба деревни» пишется
  по-разному («не восстановлена», «не восст.», «с част -восст»,
  «Восстановлено 35 дворов»): известные написания приводятся к словам,
  прочие идут как есть. «Заметки» — сельсовет, а чаще числовой код
  («4342», «442») или та же судьба деревни: в описание не идут, лежат
  в `extra["narb"]`. Блок «Ссылки на медиафайлы» — сканы,
  фотографии, письма ветеранов — не разбирается. Пустые ячейки и «NULL» —
  пусто. Незнакомое поле или пропавшее обязательное — остановка обхода.
- **Сведение с набором.** Основное правило — название и район: ключ
  названия без знаков и «ё», район сравнивается с довоенным и нынешним
  районом карточки с поправкой на одну букву («Дубровенский» —
  «Дубровненский»); совпадение сожжённых дворов и убитых различает
  одноимённые деревни одного района. Запасные правила записываются в
  `extra["narb_match"]` отдельно: «название и числа, район другой» и «район
  и числа, название другое» (у Жукова «Абразеево», в базе «Образеево» —
  13 дворов и 51 погибший, Дриссенский район). Два равных кандидата — не
  сведение. Сведённая карточка даёт записи ссылку `url`, дворы и жителей до
  войны, шифр и судьбу деревни в `summary` и все поля в `extra["narb"]`;
  если дата карточки называет день внутри месяца набора — точность «день»;
  если месяцы расходятся, интервал расширяется на оба, а
  `extra["dates_agree"] = false`.
- **Проба.** `--probe --sample 200` — 200 карточек, равномерно

  району и числам, 6 по названию и району, одна по названию и числам при

  несведённые — в основном деревни, которых у Жукова нет (Королевищи
  Минского района, Попельники Юратишковского). Дата словами есть у 155
  карточек из 200, архивный шифр или ссылка на книгу — у 177. Обрывов
  соединения — 38 на 210 запросов.
- **Сборка на кэше 24.10.2026.** В кэше 228 карточек (проба и первые
  карточки по алфавиту): 199 сведены (200 записей набора — одна карточка
  у двойников), 29 стали записями без точки. Из 165 записей набора,
  получивших карточку с датой, месяц совпал у 144; у 21 не совпал —

- **Двойники.** 19 деревень записаны в наборе дважды — то же название,
  район, числа и точка, разные `VIL_ID` (две строки «Клины» Пропойского
  района, 39 дворов и 4 погибших). Обе строки остаются, точка за ними
  сохраняется, карточка НАРБ достаётся обеим.
- **Карточки без пары** становятся записями без точки (охват «район в
  области», категория «… (только база НАРБ)»). `--build` пишет всё, что
  есть в кэше, поэтому до полного обхода таких записей столько, сколько
  несведённых карточек в пробе.

Выгрузка: `geojson/burned_villages_by.geojson` — 3 552 точки (общие
свойства вынесены на уровень слоя, `hoist_shared`), около 4 МБ;
`burned_villages_by.json` — записи без точки, около 8 МБ; полный слой —
`jsonl/burned_villages_by.jsonl`, в репозиторий не идёт.

## Границы

Границы губерний, уездов и государств нужны проекту **как подложка карты**, а
не как часть подбора контекста: подбор по территории идёт по названию
губернии (`histctx.geo.region_key`). Поэтому полигоны не переводятся в записи
схемы — они забираются, отбираются по охвату РИ/СССР и кладутся рядом с
выгрузкой как отдельные GeoJSON-файлы.

Отбираются, а не обрезаются: обрезанная граница — это уже не граница, а её
пересечение с нашей рамкой, и на карте она врала бы. Единица, заходящая в
охват, берётся целиком.

Источники и права — раздел 3 в `docs/CATALOG.md`. Проект некоммерческий,
поэтому наборы под CC BY-NC-SA (в том числе CShapes 2.0) использовать можно;
если это когда-нибудь изменится, такие слои надо будет отключить — в
`registry.py` условие записано в поле `license` каждого слоя. Общее правило
прав — условие 3 раздела «Каталог открыт»: невыясненная лицензия сбор не
отменяет, а ограничивает его фактами и ссылкой, без выгрузки чужих файлов.

Собраны три набора, и они не заменяют друг друга: heiDATA (CC BY 4.0) даёт
99 губерний 1897 года и 67 союзных единиц 1926-го с итогами переписи, RISTAT
(CC0) — 824 уезда и 103 губернии 1897 года без чисел, CShapes 2.0
(CC BY-NC-SA 4.0) — 151 период 46 государств 1886–1960 годов, границы и
столицы по датам их изменения. Файлы: `boundaries_1897`, `boundaries_1926`,
`provinces_1897`, `districts_1897`, `state_borders` — все в
`data/out/boundaries/`. Шейпфайл и GeoPackage читаются своим разбором на
стандартной библиотеке: `src/histctx/sources/shapefile.py` и `geopackage.py`,
чтобы не тянуть geopandas с fiona ради трёх наборов.

Четвёртый набор — районы УССР 1922–1937 годов с сервера HURI MAPA
(`ukraine_admin_1922_1937`, `ukraine_centers_1922_1937`): права у него не
выяснены, но граница — факт, и она берётся со ссылкой; ArcGIS REST отдаёт
JSON, и разбор у него свой (раздел «Районы УССР и перепись 1926 года»).

Первым двум наборам отбор по охвату РИ/СССР не нужен: они и составлены по
нему. CShapes составлен по миру, и отбор к нему применяется — по вершинам
границы, а не по описанному прямоугольнику: у России прямоугольник растянут
от −180° до 180° из-за Чукотки, и по нему в слой попало бы полмира.
