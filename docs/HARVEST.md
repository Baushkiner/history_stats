# Сбор данных: что откуда и как запускать

Репозиторий приводит разные источники к одной записи «что, где, когда,
откуда». Здесь — как этот сбор запускается на практике: какие домены нужны,
какой скрипт что делает и в каком порядке.

## Порядок

```bash
# 0. Ядро: нормализовать исходные файлы проекта и подборку событий
python3 scripts/build_core.py

# 1. Викиданные: сверка Q-номеров, живая проба, потом сбор
python3 scripts/harvest.py --check
python3 scripts/harvest.py --probe --layer churches
python3 scripts/harvest.py --all

# 2. Фотографии PastVu: сначала проба формата ответа
python3 scripts/harvest_pastvu.py --probe
python3 scripts/harvest_pastvu.py --all --step 0.5

# 3. Населённые места: сети не требуют, набор идёт вместе с пакетом
pip install geonamescache
python3 scripts/harvest_geonames.py --probe
python3 scripts/harvest_geonames.py --build

# 4. Погода: сначала проба ряда, потом сборка слоёв
python3 scripts/harvest_weather.py --probe data/raw/meteo/*.csv --map "..."
python3 scripts/harvest_weather.py --build data/raw/meteo/*.csv --map "..." \
    --source "ВНИИГМИ-МЦД, meteo.ru" --url "http://meteo.ru/data"

# 5. Лагерные управления: сначала проверка ответа API
python3 scripts/harvest_gulag.py --check
python3 scripts/harvest_gulag.py --build

# 6. Границы и итоги переписей: heiDATA (CC BY 4.0) и RISTAT (CC0)
python3 scripts/harvest_admin_gis.py --check
python3 scripts/harvest_admin_gis.py --build

# 7. Границы государств 1886–1960: CShapes 2.0 (CC BY-NC-SA 4.0)
python3 scripts/harvest_cshapes.py --check
python3 scripts/harvest_cshapes.py --build
# 5. Урожай и цены по губерниям (RISTAT/ERRHS): сначала проба одной таблицы
python3 scripts/harvest_errhs.py --check
python3 scripts/harvest_errhs.py --build
# 7. Засухи по годичным кольцам: сначала проба формата набора
python3 scripts/harvest_drought.py --probe
python3 scripts/harvest_drought.py --build
```

Населённые места — единственный слой, который собирается в закрытом
окружении: реестры пакетов (`pypi.org`, `files.pythonhosted.org`) открыты там,
где закрыты сайты источников, а набор GeoNames приезжает внутри пакета
`geonamescache`. Данные под CC BY 4.0 — ссылка на GeoNames проставляется в
каждой записи.

Границы и переписи скачиваются один раз и остаются в `data/cache/boundaries/`:
наборы весят мегабайты и с 2015 года не менялись. Кэш в репозиторий не идёт
(`data/cache/` в `.gitignore`), пересобрать его — тот же `--build`.

## Викиданные: сбор в две ступени

Первая редакция запросов отбирала объекты географической рамкой
(`SERVICE wikibase:box`) поверх транзитивного замыкания по классу
(`wdt:P31/wdt:P279*`). Против живого сервиса такой запрос не выполняется:
рамка РИ/СССР слишком велика, и сбор упирается в лимит времени — HTTP 504.
Проверено на всех одиннадцати запросах: не прошёл ни один. Ни `--paged`, ни
`--page-size` не помогают — `ORDER BY ?item` поверх такого результата сам по
себе неподъёмен.

Рабочий способ — отбор по государству (`wdt:P17`) вместо рамки и разделение
работы на две ступени:

1. **Список Q-номеров с координатами** — по одному запросу на государство.
   Без меток, без `OPTIONAL`, без сортировки: только то, что дёшево.
2. **Подробности к ним** — чанками по тысяче через `VALUES ?item`. Дорогие
   соединения выполняются на заранее известном списке, а не на результате
   поиска, и укладываются в лимит.

Территорию РИ/СССР не покрывает ни одно нынешнее государство, поэтому обход
идёт по семнадцати государствам-преемникам (`COUNTRIES` в
`src/histctx/sources/wikidata.py`). Рамка остаётся вторым ситом: координата
всё равно проверяется через `histctx.geo.in_bbox`.

Слой переводится на новый способ директивой `@scope country` в заголовке
`.rq`. Собираются те классы, что объявлены директивами `@qid`, — отдельного
списка классов не нужно. Сузить отбор можно директивой `@filter`, её строки
попадают в условие первой ступени. Файлы без `@scope` работают по-старому.

Дату объекта вторая ступень спрашивает у двух свойств: сначала P571 («дата
основания»), а если её нет — P1619 («дата официального открытия»). Для станций
это решает всё: на выборке в 2003 объекта по России P571 нашлась у 124 (6%),
P1619 — у 1291 (64%). Слоям, где P1619 не заполняют, добавка ничего не меняет;
событий (`@kind event`) она не касается — у них свои свойства.

Три вещи, без которых сбор снова упрётся в лимиты:

- **`Accept-Encoding: gzip`.** Ответ на десятки тысяч строк сжимается примерно
  вдесятеро. Дело не в трафике: несжатый ответ дольше течёт по сети и успевает
  оборваться на середине — разбор падает на неполном JSON.
- **Пауза между обращениями.** Сервис ограничивает не только время запроса, но
  и частоту: пачка запросов подряд получает
  `429 Aggressively rate-limiting to 1 req / min`, и это состояние держится.
  Пауза (`MIN_INTERVAL_SEC`) считается на весь процесс, отступ после 429 —
  полторы минуты.
- **Дедупликация по Q-номеру.** Многозначные `P31`, `P131` и `P625` множат
  строки: тысяча Q-номеров даёт около двух тысяч строк. Ключ — именно
  Q-номер, а не `uid`: `uid` считается в том числе от координаты, и объект
  с двумя значениями `P625` остался бы на карте дважды.

Первый запуск слоя — всегда `--probe`: он собирает одну Россию, ничего не
пишет и печатает статистику с примерами. Запрос, который не выполняется или
отдаёт пусто, должен быть виден сразу, а не через сорок минут обхода.

## Погода: приведённый ряд

У метеоданных форматов много, поэтому скачивание и разбор конкретного файла
отделены от расчёта. Любой источник сначала переводится в общий вид — обычный
CSV с такими колонками (имена задаются ключом `--map`, порядок неважен):

| Колонка | Что | Обязательна |
|---|---|---|
| `station_id` | Код станции | да |
| `year`, `month` | Год и месяц наблюдения | да |
| `name` | Название станции | нет |
| `lat`, `lon` | Координаты станции | для точечного слоя |
| `region` | Губерния или область | для слоя по губерниям |
| `tavg` | Средняя температура месяца, °C | одна из двух |
| `prcp` | Сумма осадков за месяц, мм | одна из двух |

Пример перевода из файла с русскими заголовками:

```bash
python3 scripts/harvest_weather.py --probe data/raw/meteo/samara.csv \
    --map "СТАНЦИЯ=station_id,НАЗВАНИЕ=name,ШИРОТА=lat,ДОЛГОТА=lon,\
ГУБЕРНИЯ=region,ГОД=year,МЕС=month,ТЕМП=tavg,ОСАДКИ=prcp"
```

Пропуски в рядах (`-9999`, `9999`, пустая строка) распознаются и не считаются
значениями. Строка с неразобранной датой пропускается, а вот файл без
обязательных колонок останавливает сбор с перечнем того, что в нём нашлось.

### Что считается аномалией

В слой идёт не погода, а её отклонения: обычный год — это шум, который на
карте вытеснит собой то, что действительно объясняет факт. Год попадает в
выгрузку, если выполнены **оба** условия:

1. отклонение от нормы не меньше 1.5σ (порог меняется ключом `--threshold`);
2. отклонение велико само по себе — засуха: осадков ≤ 75% нормы; дождливое
   лето: ≥ 130%; суровая зима: ≥ 2 °C ниже нормы; холодное лето: ≥ 1.5 °C
   ниже; жаркое лето: ≥ 1.5 °C выше.

Второе условие нужно из-за первого: в ровном ряду самый сухой год всё равно
окажется «выпадающим» по σ, даже если осадков было меньше всего на четверть.

Норма считается по самому ряду, а не по климатическому периоду 1961–1990:
интерес проекта — 1800–1960 годы, и норма по более поздним данным сдвинула бы
все оценки. Плата за это — ряд короче 15 лет к расчёту не допускается.

Слоёв на выходе два: `weather_stations` — точки станций с годом аномалии,
`weather_regions` — то же, осреднённое по губернии (нужно не меньше двух
станций в губернии). Второй слой существует потому, что до 1880-х годов
станций единицы, а губерния у факта из метрики известна почти всегда.

## Урожай и цены: выгрузка RISTAT

Файловый каталог `ristat.org` не отдаёт файл по постоянному адресу: архив
собирается под запрос, и обойти это нельзя. Сборщик повторяет те же три шага,
что делает человек, — берёт со страницы `form_build_id`, отправляет форму с
отметкой нужной темы и среза и скачивает архив по одноразовой ссылке с
`etl.ristat.org`. Скачанное кладётся в `data/raw/ristat` (в репозиторий не
идёт): пересобирать слой чаще, чем меняются данные, — обычное дело, а дёргать
сайт ради этого незачем.

Берётся русская версия каталога. Английская отдаёт то же самое, но названиями
вроде «Tambov governorate», и их пришлось бы сопоставлять с русскими вручную;
русская выгрузка совпадает с названием губернии из метрической книги как есть.

Значения в выгрузке **уже расшифрованы**: портал применяет к таблице словарь
`Vocabularies RISTAT`, и территория, показатель и единица приходят словами.
Те же наборы в репозитории IISH закрыты — файлы помечены `restricted`, а в
карточке набора сказано, где открыто: «Accessible at http://ristat.org».

Берутся четыре темы за четыре опорных среза (1795, 1858, 1897, 1959; срез
2002 года за пределами окна проекта):

| Тема | Что в ней | Срезы |
|---|---|---|
| `4.01` | Продукция сельского хозяйства в рублях | 1795, 1858, 1897, 1959 |
| `4.02` | Она же в натуре: посев, урожай, поголовье, падёж скота | 1795, 1858, 1897, 1959 |
| `7.03` | Цены на землю, рублей за десятину | 1897 |
| `7.04` | Арендная плата за землю | 1897 |

Срезы 1795 и 1858 годов дают посев и урожай в одних единицах, и сборщик
сводит такую пару в одну запись с отношением **сам-N** — той мерой урожая,
которой мерили современники. Ниже сам-3 после вычета семян на новый сев
остаётся вдвое меньше собранного, и запись прямо называет это недородом:
голое «снято 363 308 четвертей» не объясняет ничего, пока не сказано, много
это или мало. Пара, которую свести нельзя (посеяно ноль, единицы разные, на
показатель несколько строк из разных источников), в одну запись не сливается:
обе строки идут в слой порознь.

Права: выгрузка идёт по CC BY-NC-SA 4.0 — это условие принимается на самом
сайте перед скачиванием, и ссылка на Кесслера и Маркевича обязательна.
Проект некоммерческий, поэтому условие NC не мешает; если это изменится, слой
придётся отключить.
## Засухи по годичным кольцам

Станции начинаются с 1881 года, и дальше этой границы погодные слои не
заглядывают. Голодные годы XVII–XVIII веков объясняют годичные кольца
деревьев: по их ширине восстанавливается летняя засушливость — сеточный
индекс PDSI с датировкой до года. Разбор — `src/histctx/sources/drought.py`,
сбор — `scripts/harvest_drought.py`, тесты — `tests/test_drought.py`.

Наборы NOAA Paleoclimatology, оба — общественное достояние, оба устроены
одинаково: таблица узлов сетки плюс матрица «строка — год, колонка — узел».

| Ключ | Набор | Охват | Годы |
|---|---|---|---|
| `erda` (по умолчанию) | European Russia Drought Atlas, 4259 узлов сетки 0.5° | 22–62° в. д., 41–71.5° с. ш. — до Урала | 1400–2016 |
| `owda` | Old World Drought Atlas | −11.75–44.75° в. д. — Европа и Средиземноморье | 0–2012 |

Основным взят ERDA, хотя в каталоге назван был OWDA: OWDA обрывается на
44.75° в. д., то есть на середине империи, а в общей полосе, по словам самих
авторов, менее точен. OWDA берётся ключом `--dataset owda` ради западной
кромки — Царства Польского западнее 22° в. д., куда ERDA не дотягивается;
матрица его весит 87 МБ, поэтому годы отсеиваются прямо при чтении.

Наборы перекрываются, и в перекрытии одна и та же засуха попала бы в слой
дважды. Поэтому второй набор берётся **только кромкой**: узлы внутри охвата
основного выбрасываются (`--whole` отменяет обрезку), а файл получает своё имя
— `drought_atlas_owda.geojson`. Собрать OWDA поверх ERDA под одним именем
нельзя: это молча подменило бы слой другим, вдвое меньшим. В кромку, кроме
Польши, попадают Балканы и Малая Азия — они внутри рамки проекта
(`histctx.geo.BBOX_RU`), но за пределами империи; рамка одна на все слои, и
отдельного сита у этого слоя нет.

Собранный слой — 26,9 МБ на 28 710 записей: это самый большой файл выгрузки,
и пересобирается он за шесть секунд, а скачанные наборы остаются
в `data/cache/drought/` (в репозиторий кэш не идёт).

### Что считается засухой

Правило то же, что у погоды: в слой идёт не погода, а отклонение от нормы.
Разница одна — считать это отклонение не приходится. PDSI уже нормирован и
уже имеет общепринятую шкалу Палмера: −2 — умеренная засуха, −3 — сильная,
−4 и ниже — экстремальная. Порог по умолчанию — **−4** и меняется ключом
`--threshold`.

Почему не −3, хотя это и есть «сильная засуха»: сетка частая, а засуха —
явление широкое, и при −3 условие выполняется у каждого шестнадцатого
узла-года. Слой перестаёт быть слоем событий и становится полем: 94 248
узлов-лет и 72 602 записи за 1600–1960 годы против 33 019 и 28 710 при −4.
Экстремальная засуха — это тот случай, когда хлеб не родился совсем, и именно
он объясняет запись в метрической книге; кому нужна полная картина, ставит
`--threshold -3`.

Годы по умолчанию — 1600–1960 (`--year-from`, `--year-to`). Нижняя граница —
начало XVII века: раньше личных документов о простых родах почти не остаётся,
и объяснять становится нечего; сам атлас доходит до 1400 года. Соседние сухие
годы сводятся в один эпизод: два сухих года подряд — это один голод, а не два
события, хлеба не стало в первый год, а умирали во второй.

Сверка на известном: лето 1891 года, с которого начался голод в Поволжье,
стоит в наборе как PDSI −4.4 у Самары, −4.0 у Тамбова и −4.2 у Саратова в
следующем, 1892-м. А про голод 1601–1603 годов слой молчит — и правильно: тот
голод случился не от суши, а от холодных дождливых лет, засухи в кольцах за
эти годы нет. Слой отвечает за одну причину из нескольких и чужих на себя не
берёт; остальные — за слоем `weather_chronicles`.

### Узел сетки — не населённое место

Запись остаётся точечной (`scope = point`), но губерния и уезд у неё пустые.
`histctx.geo.extract_region` достаёт губернию из текста, а у координаты текста
нет: приписать узлу «Самарскую губернию» значило бы её выдумать. Подбор по
этому слою идёт по расстоянию, и шаг сетки (около 30×55 км) мельче обычного
радиуса подбора в 50 км — ближайший узел найдётся почти у любого села внутри
охвата атласа. Место в записи названо координатой: «узел сетки 53.75° с. ш.,
50.25° в. д.».

**Покрытие — главное ограничение слоя.** Реконструкция есть там, где растут
долгоживущие деревья и собраны хронологии: густо на западе и в центре, реже
к юго-востоку, и нигде за Уралом — восточная граница ERDA 62° в. д. Для факта
из Тобольска или с Амура слой не даст ничего, и это значит «атлас сюда не
дотянулся», а не «засух не было». Ограничение записано в карточке слоя
(`description`), печатается пробой и сборкой, а узлы на самом краю сетки —
576 из 4259 — помечены `confidence = grid_edge`: с одной стороны от них
хронологий нет вовсе.

## Границы

Границы губерний, уездов и государств нужны проекту **как подложка карты**, а
не как часть подбора контекста: подбор по территории идёт по названию
губернии (`histctx.geo.region_key`). Поэтому полигоны не переводятся в записи
схемы — они забираются, отбираются по охвату РИ/СССР и кладутся рядом с
выгрузкой как отдельные GeoJSON-файлы.

Отбираются, а не обрезаются: обрезанная граница — это уже не граница, а её
пересечение с нашей рамкой, и на карте она врала бы. Единица, заходящая в
охват, берётся целиком.

Источники и права — раздел 3 в `docs/CATALOG.md`. Проект некоммерческий,
поэтому наборы под CC BY-NC-SA (в том числе CShapes 2.0) использовать можно;
если это когда-нибудь изменится, такие слои надо будет отключить — в
`registry.py` условие записано в поле `license` каждого слоя. Общее правило
прав — условие 3 раздела «Каталог открыт»: невыясненная лицензия сбор не
отменяет, а ограничивает его фактами и ссылкой, без выгрузки чужих файлов.

Собраны три набора, и они не заменяют друг друга: heiDATA (CC BY 4.0) даёт
99 губерний 1897 года и 67 союзных единиц 1926-го с итогами переписи, RISTAT
(CC0) — 824 уезда и 103 губернии 1897 года без чисел, CShapes 2.0
(CC BY-NC-SA 4.0) — 151 период 46 государств 1886–1960 годов, границы и
столицы по датам их изменения. Файлы: `boundaries_1897`, `boundaries_1926`,
`provinces_1897`, `districts_1897`, `state_borders` — все в
`data/out/boundaries/`. Шейпфайл и GeoPackage читаются своим разбором на
стандартной библиотеке: `src/histctx/sources/shapefile.py` и `geopackage.py`,
чтобы не тянуть geopandas с fiona ради трёх наборов.

Первым двум наборам отбор по охвату РИ/СССР не нужен: они и составлены по
нему. CShapes составлен по миру, и отбор к нему применяется — по вершинам
границы, а не по описанному прямоугольнику: у России прямоугольник растянут
от −180° до 180° из-за Чукотки, и по нему в слой попало бы полмира.
