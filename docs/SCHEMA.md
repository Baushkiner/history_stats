# Схема записи контекста

Все слои приводятся к одной записи. Это позволяет искать контекст по всему
массиву одним запросом, а не писать отдельную логику под каждый источник.

Версия схемы: `1.1` (константа `histctx.SCHEMA_VERSION`). В 1.1 добавлены поля
`scope` и `regions` — событие может действовать на территории, а не в точке.

## Поля

| Поле | Заголовок в XLSX | Тип | Описание |
|---|---|---|---|
| `uid` | UID | строка | Стабильный идентификатор `<слой>:<хеш>`. Не меняется при пересборке, если запись не менялась |
| `layer` | Слой | строка | Машинный код слоя: `churches`, `battles`, … |
| `layer_title` | Название слоя | строка | Человекочитаемое название |
| `group` | Группа | строка | `admin`, `faith`, `hardship`, `economy`, `culture`, `military` |
| `title` | Название | строка | Заголовок записи |
| `category` | Категория | строка | Уточнение внутри слоя: жанр, тип храма, название войны |
| `lat` / `lon` | Широта / Долгота | число | WGS-84. В GeoJSON порядок обратный: `[lon, lat]` |
| `scope` | Охват | строка | `point`, `region` или `state`. См. ниже |
| `place_text` | Территория | строка | Исходное текстовое описание места |
| `region` | Губерния/область | строка | Извлечённая единица: «Нижегородская губерния» |
| `regions` | Затронутые губернии | список | Только для `scope = region`: где событие действовало. В XLSX и GeoJSON — строка через «; » |
| `district` | Уезд/район | строка | Извлечённый уезд, если назван |
| `year_from` / `year_to` | Год от / Год до | целое | **Числовые границы — основа подбора по времени** |
| `date_precision` | Точность даты | строка | См. ниже |
| `date_approx` | Дата приблизительна | да/нет | Взведён при «примерно», «около», «накануне» |
| `period_raw` | Период (исходный текст) | строка | Исходная запись датировки — всегда сохраняется |
| `actor` | Автор/действующее лицо | строка | Автор произведения, фотограф, ведомство |
| `work` | Произведение/событие | строка | Название книги, войны, кампании |
| `summary` | Описание | строка | Краткое пояснение |
| `quote` | Цитата | строка | Прямая цитата очевидца |
| `url` | Ссылка | строка | Ссылка на источник |
| `image_url` | Изображение | строка | Прямая ссылка на изображение |
| `source` | Источник | строка | Откуда взято |
| `source_id` | ID в источнике | строка | Q-номер, внутренний ID |
| `license` | Лицензия | строка | Условия использования |
| `confidence` | Достоверность | строка | См. ниже |

## `scope` — где событие произошло

| Значение | Что означает | Как подбирается | В GeoJSON |
|---|---|---|---|
| `point` | Объект или событие в точке: храм, фотография, сражение | по расстоянию от факта | да |
| `region` | Действовало в перечисленных губерниях: голод 1891 года, депортация | по совпадению губернии | нет, геометрии нет |
| `state` | Действовало на всей территории: ревизия, воинская повинность | всегда, если совпало по годам | нет, геометрии нет |

Поле появилось потому, что самое ценное для генеалогии — не точка. Отмена
крепостного права, ревизия, голод, мобилизация объясняют документ о предке
лучше, чем соседний храм, но координат у них нет и быть не может. Ставить
такому событию точку в столице губернии — выдумка: на карте она выглядит
достоверно и вводит в заблуждение.

Записи с `scope = region` и `state` не попадают в GeoJSON (там нечего рисовать),
а выгружаются в `data/out/territorial_events.json` и в общий `context.jsonl`.

## `date_precision`

От точного к грубому: `day`, `month`, `season`, `year`, `decade`, `part`
(часть века), `century`, `era` (именованная эпоха), `unknown`.

Поле нужно не для красоты: запись «19 в.» формально подходит почти к любому
факту XIX века, поэтому при ранжировании широкие датировки понижаются.

## `confidence`

| Значение | Что означает | На карте |
|---|---|---|
| `ok` | Проверок не нарушено | да |
| `place_level` | Координата указывает на населённый пункт, а не на само место события | да |
| `no_coords` | Координат нет | нет |
| `outside_bbox` | Координаты вне охвата РИ/СССР | нет, но запись сохранена |
| `not_an_event` | Это воинская часть, корабль или персоналия, а не событие на местности | нет |

Ничего не удаляется молча: спорные записи помечаются и остаются в выгрузке.

## Правило расширения интервала

При неоднозначной датировке интервал **расширяется, а не сужается**. Для подбора
контекста потерять релевантную запись хуже, чем показать лишнюю: лишнюю
исследователь отсеет глазами, а о пропавшей не узнает. Насколько огрублена
датировка, видно в `date_precision`.

Пример: «19 в. (начиная с 1840-х гг.)» разбирается как 1801–1900, а не 1840–1900.
Скобочное уточнение сохраняется в `period_raw`.

## Второй приведённый формат: ряд наблюдений

Схема выше описывает **запись контекста** — то, что показывается рядом с
фактом. У погоды промежуточная ступень: сначала любой источник переводится в
общий вид ряда (`station_id, name, lat, lon, region, year, month, tavg, prcp`),
и только потом из него считаются отклонения от нормы и строятся записи этой
схемы. Ряд — не контекст: «средняя температура июля 1891 года» ничего не
объясняет, пока не сказано, насколько это отличается от обычного года.

Формат ряда и пороги аномалий — `docs/HARVEST.md`, расчёт —
`histctx.sources.weather`.

## Форматы выгрузки

| Файл | Назначение |
|---|---|
| `data/out/geojson/<слой>.geojson` | Слой для карты, `FeatureCollection`, CRS84 |
| `data/out/territorial_events.json` | События без геометрии: `{name, count, records}` |
| `data/out/weather_regions.json` | Погодные аномалии по губерниям, тот же вид |
| `data/out/name_variants.json` | Указатель написаний: `{geonameid: {title, lat, lon, names}}` |
| `data/out/all_layers.xlsx` | Все слои, по вкладке на слой, русские заголовки |
| `data/out/context.jsonl` | Построчный JSON: загрузка в базу, читаемые диффы в git |
| `data/out/report.md` | Отчёт о качестве данных |

В GeoJSON пустые свойства опускаются — файл заметно легче, а на карте это
ничего не меняет.
